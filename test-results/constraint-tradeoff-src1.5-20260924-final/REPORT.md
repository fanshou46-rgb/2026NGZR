# src1.5 约束换目标实测（2026-09-24）

本文件记录修改前的基线。约束收益规划的实现与复测见[新报告](../constraint-tradeoff-src1.5-20260924-implemented/REPORT.md)。

结论：现有代码能执行六个收益为正的交换题，但不能可靠地决定何时**不**牺牲约束。唯一应停手的负收益题仍被执行，基础分从 100 降到 74。正收益题的成功也不能解释为代码已经具备组合规划：关键题的首步预测效用为 −26，却仍按旧任务顺序执行。

测试对象为仓库 `66f8990` 的 `src1.5`，策略源码未改。评分平台使用用户提供的 `EvaluationEnvironment.zip`（SHA-256：`FE41BA5F892CA479AF8F15F4526780B2A25A82A4951E12206E7BE6ABB40E6A24`）的 **2026 SDK 原源码**，在 Ubuntu 18.04 / g++ 7.5.0 上重编。压缩包内预编译程序需要本机没有的较新 glibc/libstdc++，所以本次运行的不是原封不动的预编译二进制；规则和 SDK 源码未改。`src1.5/words.txt` 在 Windows 检出为 CRLF，运行器仅在临时输出目录生成 LF 副本，避免词典换行造成误判，未修改仓库词典。编译文件哈希见 [`build/build.json`](build/build.json)。

每题运行 IT 和 NT，两模式结果与动作序列一致。表中目标／约束是结束时官方评分平台的计数；“基础分差”是本客户端减去不动作对照，使用 `40 × 目标 + 20 × 约束 − 动作成本`；“官方分差”还含时间分。同题两模式数值相同。

## 定向修复方案（尚未实施）

1. 在候选选择层加入小范围组合前瞻：对共享同一约束的 2–4 个目标任务和必要的收尾动作做隔离沙盒模拟。累计最终满足目标、一次性的约束损失、全部动作成本与剩余期限，计算整组基础分差。不能把同一约束损失按目标重复扣分。
2. 用组合净收益作“允许负收益首步”的门槛。只有可完整执行且组合净收益大于 0 时，才放行首步；否则跳过会降低分数的候选。将判断接入主循环、检查阶段和 `must-choose-one`，避免后续路径绕过门槛；其余不相关任务维持现有行为。
3. Stage 2 在关键感知或动作反馈改变世界状态后重新评估组合，若剩余任务不能兑现正收益，则停止追加破约束动作。保留 5 秒期限和安全余量，不做跨题参数学习。
4. 修复后验收：01 不动作且基础分至少 100；02–06 与原题 07 保持正收益；IT／NT 都通过，并回归原有原型题和有效赛题。此处仅提供测试与设计，没有改动策略代码。

定位依据：[`rdfw.cpp`](../../src1.5/rdfw.cpp) 的 `EvaluateShadowCandidates` 虽按效用排序，但 `ExecuteMainTaskLoop` 仍以 `FindCandidate(candidates, task_index)` 选旧顺序任务；`CanStartPlan` 主要检查期限，不把负收益作为阻止条件。现有单候选预测无法识别需要多个任务才能兑现的净收益。
