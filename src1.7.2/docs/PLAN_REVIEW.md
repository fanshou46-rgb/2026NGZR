# src1.7.2 实施与复核边界

基线：upstream/main 4b0f3f3e，src1.7.1。已有版本保持原样。

1. AskLoc 是带噪观测。概率分布只用于探测排序；同一回答不重复累积置信度，not_known 不增加信息。保留位置/容器联合假设及未知质量。可信事实、Sense 和动作证据继续由 canonical 管理。
2. 新增单次 AskLoc；下一轮重新规划，不能预先授权按回答执行整条动作链。开柜观察仅允许已确认位置、空手、已关闭的容器，并检查整段 Move/Open 的约束与目标损失；失败或超时立即重规划。
3. 同一探测的重试限制只约束该探测；保留每题总次数、总成本和时间限制。避免两次无效探测误关整个探索层。
4. 排序使用带概率的下游收益估计与动作成本、后续执行时间。该值是启发式估计，不是已经标定的成功率；不能据此放宽动作安全条件。
5. Stage 2 短任务组仅在无询问/感知假设的完整投影可证明改进时授权；失败立即退出。成功后被别的动作破坏的目标可恢复，失败重试仍受次数限制。
6. 使用单元测试验证错误/重复/未知回答、可信事实冲突、封闭容器、局部重试、投影隔离、动作失败及预算。官方 SDK 同题配对报告目标数、历史约束、基础分、时间分和超时，公开退化案例。

不把旧版的强制执行整体恢复。完整 POMDP、学习校准与扩大探测风险预算属于后续实验，当前先建立可验证的概率接口和单步观测后重规划。

## 首轮对照后的修正

- 首轮 16 对模拟器试验暴露了询问收益过高、移动恢复目标被误拒和过早停止验证的问题，保留完整记录，不用该轮结果作为发布收益。
- 负收益的单任务若属于目标排序或恢复问题，暂停为它生成 AskLoc；信息采集不能代替任务组规划。
- Sense 的信息估计使用“至少获得一项相关事实”的概率下界，避免要求所有同地点对象同时出现；该数值与任务完成概率分开。
- 普通 Move+Sense 保留原来的目标恢复能力，估值中预留恢复已确认 GOTO 的成本与时间。Open+Sense 仍拒绝已有目标损失。
- 只有对象位置、inside、容器状态等所需输入都已确认的 Stage 2 任务，才可绕过旧风险与两约束数量门槛；收益门、历史约束记分和实际失败处理仍生效。

- 后续对照显示未经标定的期望收益会打乱原先有效的 Sense 覆盖顺序。本轮默认先保留 Sense 覆盖优先，概率用于覆盖相当的候选比较；Open+Sense、AskLoc 在现有合法 Sense 无法继续时补充。
- 独立的新 AskLoc 调用允许同对象最多三次、每题仍最多八次探测且探测成本不超过 32。重复的相同回答仍只更新 belief 一次，连续 not_known 不提高可信度。

- 22/23/24 的两个 `cons_not goto` 是记分约束。对 Move+Sense 新增最多涉及两个不同约束的单题风险额度；每项按最坏损失 20 分计入净收益，且只允许至少 200 分目标机会的探测使用。Open+Sense 的无损失门槛继续保留。每次授权与累计风险数量均记录到 `probe.v2` 日志。
- 下游机会按相同对象/目标绑定的重复目标成组，并最多计三个不同执行组；不再假设一次询问就能完成全部 34 个目标。成本和时间也按组预留。
- 一旦拿到可用的回答，必须等相关证据发生变化后才可再次询问同一个对象；not_known 的少量重问例外不会累积可信度。

## 多种子复核后的最终修正

完整初稿 142 对基础分 +3092、目标 +95，但额外种子 20260925 的 c011 / 原 14.xml / IT 暴露 Sense 覆盖相同的候选被新收益估计改序，较有用的后续探索赶不上时限，目标 2→1。最终保留 Sense 的完整原排序，不再用未经校准的估值打破其同覆盖排序；新估值用于资格检查与询问排序。新增该行为的回归测试，普通测试增加到 200 项。初稿源码、142 对完整结果和该种子 16 对结果单独保留；未开始实际运行的第二种子中止以进行修正，最终在新目录重跑。

## SDK 超时清理竞态

第二轮完整对照发现 src1.7.2 在 c001 IT / c019 NT 超时后出现 SIGSEGV；随后同一 SDK 对照中 src1.7.1 也出现此类崩溃。SDK `plug.cpp` 的 `timed_join` 未确认规划线程退出便发送结束并调用 Fini；原 Fini 当场清空对象/任务，仍在运行的规划线程继续访问失效状态。不能把这类结果计作正常完成。

src1.7.2 新增规划生命周期互斥和独立原子取消标记。Fini 先取消未来的真实平台动作，再等待 Plan 退出后清理；正在等待反馈的动作可返回并按真实结果更新，后续动作拒绝。清理与下题启动串行，原失败/未知证据规则不变，SDK 源码不修改。新增实际 Plan、被阻塞平台动作和另线程 Fini 的集成测试，并验证下一题能够启动，普通测试共 201 项。修正前源码、完整结果、缺失评分和中止的第二种子均保存。

默认未优化 Debug 的 ASan/UBSan 检查中，三个 guarded 用例触发既有 25 ms 搜索预算，性能断言失败，没有内存/未定义行为报告。保留该结果，改用 Debug + O2 的插桩构建复核；保留断言及原搜索预算，不放宽生产期限或删除用例。
