# 完整概率决策执行与验收

用户已授权在独立副本优化，要求正式分提升且实际目标/基础分总体不退化；允许有依据、费用和成功失败分支的试探。三版比赛代码保持冻结，不创建1.7.8。

## 实施顺序

1. 恢复确定信息下的完整任务能力：固定搜索工作量，保留完成的候选，计入终态恢复，避免执行盈利前缀后永久停止。所有第一轮退化转为开发回归。
2. 所有真实SDK调用经过同一发送边界：准备许可、核对事实版本和期限、只发送一次、保存原始反馈、提交实际状态。未知结果不按失败处理；失败仅排除其前提能够支持的结论。
3. 持久联合信念包含独立at、多父inside、手/托盘共存、柜门与约束历史。强事实作为硬限制，弱回答只更新权重。区分未建模残余质量与场景采样误差；支持缺失不生成“确认事实”。
4. 每个实际决策比较直接任务、Sense、Open+Sense、Ask、腾手/托盘、恢复与停止。策略分支仅按公开反馈选择。先计最终目标和历史约束，再扣完整动作费用与期限；付费前缀绑定恢复分支。
5. 开发集校准先验、回答似然和SDK耗时，选定32/64/128场景与4096/8192/16384世界动作计算上限。单轮50ms、累计250ms与真实5000ms期限共同控制；墙钟保护仍保留。
6. 冻结实现后生成新的独立100题留出集，先完成参考SDK验证再观察策略成绩。九臂唯一变化消融：三版历史、机械修复、完整模型、中性、无询问更新、因子化、短视信息；IT/NT、三种子加首种子重复，共6480次新题运行，历史矩阵和结构回归另计。

## 通过条件

- SDK执行100%许可/收据覆盖；没有错误确认、过期许可、重复发送或作者真值进入策略。
- 给定相同公开历史、时间输入和工作预算，离线重放动作100%一致；真实SDK重复G/C/K一致率至少99%，所有差异有反馈或期限分支定位。
- 按场景聚类的95%区间：正式分相对两版1.6.7的改善下界大于0；目标/基础分差值下界不小于0。重复轮不作为独立样本。
- 分Stage、模式、题族报告全部退化、失败动作、截止及缺失标签。仅时间分提高或局部题族收益分别陈述。
- 若留出验收失败，该题库转为回归集；优化后使用新留出题，不在同一留出集调参再宣称独立胜出。

有限期限内只承诺有界、可执行、证据闭合的策略，不承诺全局最优。完成的检查点带源码/二进制哈希和完整结果上传云端；未完成实现不作为正式策略发布。
