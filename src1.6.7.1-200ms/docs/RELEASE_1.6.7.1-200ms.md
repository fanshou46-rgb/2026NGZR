# 1.6.7.1-200ms：基于 200ms 的 H1 强化与综合 200 题对照

日期：2026-10-06。直接基线：`src1.6.7-200ms`。本候选保留 200ms 规划安全余量，移入已有 `src1.6.7.1` 的生命周期退出保护和 `isMultiGotoMode=false` 构造初值；原 200ms、原 300ms 与 300ms H1 目录均未改动。

## 代码范围

只改变三个顶层产品文件：`CMakeLists.txt`、`rdfw.cpp`、`rdfw.hpp`。其中 `CMakeLists.txt` 更新版本号；`rdfw.cpp` 在 Plan/Fini/析构之间使用退出代次和生命周期锁，并在输入、StopGate、RecordAction 边界处理取消；`rdfw.hpp` 初始化多 GOTO 标志并保持 `plan_safety_margin{200}`。任务选择、感知、约束交换、动作费用和 5000ms SDK 期限没有改变。`tests/audit_derivation.py` 对 25 个产品文件逐字节核对：本版等于原 200ms 加上先前 300ms H1 的产品改动，除余量值和版本日志之外与 300ms H1 相同。完整差异及两版 SHA256 见 [source.diff](source.diff) 和 [DERIVATION.json](DERIVATION.json)。

## 验证协议

复用原 `题目/2026_comprehensive_200` 题目和哈希：180 道正常题、20 道刻意非法题。每题 IT/NT，两版共 400 组、800 次官方 SDK 运行，固定种子 20260928，一轮，默认策略，串行 AB/BA 交替，平台期限 5000ms。只有临时运行词表转换为 LF；官方 SDK 的 src/include/res 共 52 个文件与原安装逐字节一致，服务器和库为兼容环境重建版，两套哈希均在输入审计中。运行器冻结并在结束时重新校验源码、题目、SDK、工具和二进制。

按 SDK 答案计目标 G、约束信用 C、所有尝试动作费用 K 和基础分 B；正式分 F 为 `min(SDK 原始分, 1000)`。时间奖励单列，非法题与缺失答案不并入正常题。原始服务器动作、ASP 答案和评分经独立审计重新计算，800 次运行共 0 处不一致；种子确认 800/800，正常题无 SDK 截止、外部超时、运行失败或缺失评分。

## 专项检查与限制

普通 Release CTest **134/134 通过**，包含 8 项生命周期检查和直接 SDK 评分语义检查。将相同反例编译到未改的 200ms 原版：规划期间清理退出码 42，未初始化标志退出码 43；本候选对应普通测试通过。测试中一项 deadline 边界原先写死 300ms，已把测试预期改为 200ms，生产代码未因它调整。

O2 ASan/UBSan/泄漏配置已编译，首轮 8 项生命周期检查全部通过；之后 `input_safety_tests` 持续高 CPU 超过 6 分钟，本轮全套检查主动停止。补充的连续 CTest 运行又在不同专项用例上出现 10 秒超时，单项直接执行可通过；因此**不宣称 133/133 内存检查完成**。初始未完成日志、补充测试日志和成功的普通检查均保留。正式 SDK 运行没有这些测试超时，仍需另行解决本机连续 sanitizer 执行的不稳定性，才能把内存检查列为发布通过项。

## 结论和复核入口

这是基于原 200ms 的退出/初始化安全候选。原版在两个定向反例中失败而本版通过；综合 200 题没有改变解题动作、目标、约束或基础分。正式分 +14 属于时间奖励波动，不足以推荐因提分而替换原版。若按稳定性目的继续采用，应先补齐可重复的 sanitizer 连续检查，并用超时压力题单独验证 200ms 余量的风险。

完整逐组成绩、差异、冻结哈希、独立复算及原始证据见 [测试报告](../test-results/comprehensive200-20261006/REPORT.md)。复现工具为 `tests/run_comprehensive_compare.py`、`tests/audit_comprehensive_results.py`、`tests/compare_historical_300.py` 和 `tests/package_comprehensive_evidence.py`。
