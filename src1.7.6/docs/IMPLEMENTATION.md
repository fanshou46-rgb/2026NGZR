# src1.7.2：有界信息采集与概率接口

基线为 src1.7.1 / upstream 4b0f3f3e。旧版本未修改。本轮是可对照的实验版本，验证结论见 RELEASE_1.7.2.md。

## 决策流程

1. 初始描述、纠错信息和事实继续进入原 canonical/provenance 管理；Stage 2 初始描述与 AskLoc 仍是待验证信息。
2. 使用原主循环评估任务和停止收益。Stage 2 有界任务组仅在输入已确认、无询问或感知预测、完整路径严格改善时执行；实际状态、动作或结果不符立即退出并重规划。
3. 无合格正收益任务时分析阻塞事实。目标排序导致的负收益问题不生成多余 AskLoc。
4. 保留已有合法 Sense 的完整覆盖/价值/成本/时间/输入顺序。概率与净收益用于资格检查及 AskLoc 排序。补充已确认容器的 Open+Sense，以及单次 AskLoc。
5. 每次候选核对物理前提、完整动作白名单、历史约束与时间。只对至少 200 分目标机会的 Move+Sense 允许有界记分约束交换，每题最多涉及两项不同约束，每项按 20 分最坏损失估价；开柜观察仍要求无目标/约束损失。
6. 执行一次信息动作后重新评估任务。真实 Sense 和动作结果确认事实；询问只改变弱假设和独立 belief。
7. 使用 canonical 判断完成目标。成功后被后续动作破坏的 Stage 2 目标可以恢复，失败仍最多三次，主循环步数上限与 deadline 继续生效。

## 概率与事实

`LocationBelief` 的备选为 at(location)、inside(container)、未知。大物体只使用位置备选。初始描述的位置获得一半先验质量，其余质量分配给备选和未知；这是显式的启发式参数，未经学习校准。

询问似然参考当前 SDK 的 60% 正确、30% 随机回答、10% 不知道，随机回答域使用本地候选近似。not_known/非法回答不提高可信度；同一个回答只累计一次。可信事实冲突不被弱答案覆盖。负 Sense 只排除已经证明不在该处的外部位置，不排除封闭容器中的可能性。

`information_estimate` 表示获得至少一项相关信息的估计。`expected_gain` 是决策排序启发式，不是任务完成概率，也不进入官方评分。目标机会按相同对象/目标绑定的重复目标分组，最多估三个执行组；相应执行成本和时间一起预留。

概率再高也不会调用确认事实的接口。shadow 中的 AskLoc/Sense 不更新真实 belief。当前没有实现完整 POMDP 或学习型概率模型。

## 预算与审计

每题最多 8 次 Probe、最多 32 分探测动作成本。Probe 内同一观察身份最多 2 次（普通 Sense 按地点，开柜观察按容器），同对象探测询问最多 3 次。有效回答后要先验证，相关事实未变时不再次询问；未知回答允许有界重问。同探测无效或达到上限不会关闭其他探测。这些额度计数只针对新增 Probe，原任务内部感知/询问仍沿用原有任务预算。

`probe.v2` 记录询问回答、概率估计、收益估计、成本、约束风险、动作反馈、重规划和随后完成。评分约束历史损失不能因恢复动作而重新获得信用。

SDK 超时后可能在规划线程尚未退出时调用 Fini。新增生命周期互斥与原子取消：Fini 先禁止后续真实平台调用，等 Plan 退出再清理对象/任务；下一题重新启动时恢复运行标记。等待中的真实反馈仍按原证据规则处理，SDK 本身不修改。

## 构建与复跑

使用兼容的 Linux 官方 SDK，`tests/build_probe.sh <输出文件> <SDK目录>` 构建产品。单元测试：

```sh
cmake -Hsrc1.7.2/tests -B/tmp/rdfw18-tests -DCMAKE_BUILD_TYPE=Release -DOFFICIAL_SDK=<SDK目录>
cmake --build /tmp/rdfw18-tests -- -j4
(cd /tmp/rdfw18-tests && ctest --output-on-failure)
```

配对测试：

```sh
python3 src1.7.2/tests/run_probe_compare.py --sdk <SDK目录> --suite legacy --rounds 1 --seed 20260924 --output <全新输出目录>
```

支持 `--ids`、`--baseline-source` 和指定其他种子。复用已编译产品时必须通过源文件和二进制哈希检查。测试保留所有结果，核对输入实际字节、上游输入的换行等价性及 SDK 模型哈希。
