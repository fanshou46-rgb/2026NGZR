# 1.6.1 决策代码实现计划

日期：2026-09-25  
状态：Stage 1 受控执行已实现；其余设计建议和后续门槛以本计划为准。  
依据：[后续改进方案](PLANNER_IMPROVEMENT_PLAN.md)、[旁路搜索实施记录](SEARCH_IMPLEMENTATION.md)。

## 1. 本轮目标与边界

让任务组搜索能够改变真实任务选择，并验证它是否带来基础分收益。首个交付范围为 **Stage 1 中事实充分、完整后续可模拟的场景**，通过 `RDFW_TASK_GROUP_MODE=guarded` 启用。保留 `off` 和 `shadow`，默认切换须在验收后单独完成。

Stage 2 本轮继续运行现有策略，保留必要感知、纠错、失败恢复和终态证据检查。Stage 1 也须检查具体事实依赖，不能仅凭阶段编号认定信息完整。完整模拟暂不支持的执行分支返回原策略。

本轮不承诺原有 60 题必然涨分。最近一次配对测试中，120 组 IT／NT 配对的基础分、目标、约束和动作序列全部相同；旁路版官方总分下降 26 分，差异来自时间奖励。下一轮必须同时验证定向收益、原题逐题回归和计算耗时。[测试报告](../test-results/user-stage60-shadow-20260925/REPORT.md)

## 2. 需要补齐的决策链

```text
真实状态和执行阶段
  → 检查适用范围、剩余时间、事实依赖
  → 投影原策略完整后续
  → 搜索守约／破约任务组，在节点状态重新生成候选
  → 为入围任务组补齐后续，得到可比较的终止状态
  → 比较停止、原策略和任务组的最终基础分
  → 保存获批任务组及兑现后续
  → 动作前检查授权，执行一个任务，核对真实结果
  → 继续有效后缀，或从当前真实状态重新决策
```

任何必需的基准投影、事实检查或时间检查不完整，都不能批准新的破约任务组。限时搜索可以只探索部分候选，但每个被批准的方案及其比较基准必须完整。

### 2.1 当前代码与改造位置

| 位置 | 当前缺口 | 本轮改造 |
| --- | --- | --- |
| `BuildTaskGroupPlan()` | 手工现场快照；只投影指定任务组 | 抽取可复用投影作用域，支持完整后续、预算和退出原因 |
| `SearchTaskGroups()` | 根任务池固定；按前缀分数保留结果 | 在节点状态生成候选；前缀只作搜索排序，入围方案补齐后续 |
| `CandidatePlan` | 依赖任务索引；没有完整性、假设与承诺信息 | 增加稳定身份、事实依赖、终止原因及完整后续结果 |
| `ShouldStartConstraintTrade()` | 组合批准结果只有布尔值 | 新模式通过统一决策结果返回具体方案和损失授权 |
| 主循环、检查、恢复、`MustChooseOne()`、多 `goto` 聚合 | 各自筛选和执行；不能持续兑现同一组计划 | 抽取原策略阶段调度器；新决策入口统一处理任务组执行 |
| 原子动作包装函数 | 记录动作并调用平台后才更新约束账本 | 在计费和平台调用前检查动作前提、证据、授权及兑现时间 |

原策略中的 `risk` 门槛和 `HasRequestedTask()` 等规则需要逐处登记。新模式下，应把物理不可执行与可计分的约束损失分开；原策略分支保留原有行为。不得通过全局关闭约束检查完成接入。

## 3. 计划新增的数据与接口

建议新增 `decision_planner.hpp/.cpp`；投影作用域可放入 `planner_projection.hpp/.cpp`。执行阶段重构先保留在 `rdfw.cpp/.hpp`，避免同时大规模移动现有求解代码。

| 类型／接口 | 主要内容与职责 |
| --- | --- |
| `FormalGoalId`、`TaskRef`、`ConstraintId` | 原始正式目标和约束具有稳定身份；任务引用支持重复执行及临时任务 |
| `FactDependency` | 事实键、取值、来源、验证状态；明确哪些是假设，哪些已由真实执行确认 |
| `LegacyCursor` | 主循环／检查／多 goto／恢复阶段及各自游标、延后状态，能够准确继续原策略 |
| `ProjectionContext` | 根状态标识、CPU 截止时间、累计预算、预测动作耗时、允许的约束损失 |
| `ContinuationResult` | 终态评分、动作、任务后续、依赖、预测耗时；区分正常完成、预算中断、未知事实、不可模拟分支 |
| `DecisionResult` | `UseLegacy`、`Stop`、`ExecuteGroup`；附比较分数、选择原因和可执行方案 |
| `CommittedGroup` | 有序任务及所需后续、当前游标、已授权约束损失、预期状态、兑现条件和时间储备 |
| `ExecutionOutcome` | `Completed`、`ReplanRequired`、`Failed`、`DeadlineReached`；避免把重规划当成任务失败 |
| `ProjectLegacyContinuation()` | 从给定真实／投影状态和阶段游标运行原策略直到明确终止 |
| `DecideNext()` | 适用范围检查、预算分配、搜索、完整比较和决策 |
| `ValidateCommittedSuffix()` | 每个任务完成后，从真实状态核验剩余任务及收益条件 |
| `AuthorizeNextAction()` | 在原子动作计费和平台调用前，核验该动作是否仍获授权 |

稳定身份在解析正式目标时生成，随后穿过排序和任务优化。两个相同的正式目标仍保留两个计分身份；临时任务不新增目标奖励。一个优化任务若服务多个正式目标，应记录映射，不能靠数组下标推断。

状态签名至少覆盖物体关系、机器人位置和携带状态、事实取值及证据、任务标志、正式目标映射、永久约束账本、失败历史和阶段游标。`world_revision`、位置和已破约集合可以辅助判断，不能单独充当完整等价判据。第一轮允许不做跨决策缓存。

## 4. 完整后续的投影与比较规则

### 4.1 先重构原策略调度器

抽取一个可逐步推进的原策略调度器，复现当前主循环、`MustChooseOne()`、检查阶段、多 `goto` 聚合及终态恢复的调用顺序、门槛和退出行为。投影期间关闭新决策入口，防止递归搜索。

当前终态恢复可能在 `normal_stop_requested` 为真时仍被调用。原策略重构要保留这一行为；新决策的 `Stop` 则需要独立的终止结果，使其与“立即停止”的评分含义一致。

多 `goto` 聚合包含临时任务和末尾移动，必须完整模拟或明确标记该场景暂不支持新决策。不能用连续调用若干次 `SolveTask()` 代替完整原策略基准。

### 4.2 统一投影隔离与时间模型

- 将现有快照与恢复抽取成作用域对象，覆盖世界、任务、证据、约束矩阵、永久账本、评分器、失败记录、感知记录、阶段游标和执行标志。正常返回、异常和预算中断均恢复。
- 审计含指针的对象与容器，不能以浅拷贝整个 `RDFW` 代替现场隔离。嵌套投影须有明确所有权和动作记录归属。
- 投影不得调用真实平台接口；模拟感知产生的事实必须保留“假设”属性，不升级真实证据。
- 区分搜索 CPU 耗时和计划动作耗时。完整后续使用预测动作时间推进虚拟执行时钟；真实截止时间始终继续流逝，不能通过恢复快照重置。
- 沿用当前 4700 ms 内部时限与 300 ms 安全余量的语义，核实已有截止时间接口，避免重复扣除余量。官方评测仍为 5000 ms。

### 4.3 比较同一根状态下的可执行终态

每个入围任务组分别考虑“执行后明确停止”和“执行后继续原策略”，按相同评分规则与剩余时限评估。候选终止在不同状态是允许的，但不得遗漏仍计划执行的动作成本或尚未兑现的奖励。

所有方案统一计算：终态正式目标奖励、符合奖励资格的未永久损失约束奖励、累计动作成本。已经发生的成本和账本损失作为共同起点；同一约束失分只记一次。临时目标不计奖，必须恢复的正式目标在恢复前不能算作已兑现收益。

比较对象包括：立即停止、原策略完整后续、入围守约方案、入围破约方案。原策略后续也可能破约，应按实际账本增量分类。标为守约的方案，其后续也必须保持守约，否则重新分类并记录授权需求。

首轮仅当新方案的预测基础分严格高于原策略和停止方案，且通过执行准入时，才切换真实决策。新方案同分时保留原策略。若停止严格优于原策略及全部完整候选，可返回明确 `Stop`。搜索前缀的分数不能单独用于授权。

为控制预算，不对每个搜索节点运行完整尾部：先投影原策略基准，再扩展前缀，对守约和破约两类入围方案公平分配补齐后续的预算。基准不完整时本轮回退；某个候选不完整时丢弃该候选。不能将不完整结果的暂时高分视为可用终分。

## 5. 搜索与真实执行的接入规则

### 5.1 搜索扩展

保留束宽 6、分支宽 8、主要深度 4、最多 2 次恢复任务作为初始参数。扩展时基于投影节点的状态重新生成可用任务，允许新解锁任务和有意义的恢复执行。

前缀可以暂时亏分，也可以暂时失去正式目标。搜索排序与执行准入分开，不能沿用单任务 `marginal_score > 0` 直接淘汰所有此类前缀。守约与破约两类保留独立入围机会，记录剪枝、预算和未展开原因。

### 5.2 统一预算

单次决策 CPU 预算上限 25 ms，每题累计 100 ms，包含候选准备、快照、完整基准、搜索、评分和后缀复核。把嵌套的旧交易判断纳入同一预算，避免每层重新获得 25 ms。初始化预算起点应在候选准备之前。

在节点、任务、模拟动作及较大循环边界检查截止时间；记录单次不可中断工作造成的超额。真实动作使用独立的剩余执行时间判断。预算不足时执行原策略，并记录回退原因。

### 5.3 获批组的持续执行

`CommittedGroup` 保存产生收益结论所依赖的全部后续。如果收益依赖原策略尾部中的恢复动作，该尾部也属于兑现承诺，不能只保存搜索前缀。

启动前预留整组兑现所需的动作时间及复核开销。逐任务执行，每次完成后核验真实状态、依赖与剩余时间。后缀仍有效时继续；更换方案必须重新比较完整结果，不能因为第一步已经执行就随意丢弃后续。

对同一任务内部的每个原子动作，在 `RecordAction()` 和 `Plug` 调用前检查：物理前提、事实依赖、即将新增的约束损失是否在显式授权集合内、剩余时间是否允许兑现。检查约束账本的时点必须早于破坏动作，不能只依赖动作后的 `UpdateConstraintLedger()`。

感知或失败导致事实冲突时，立即阻止下一项尚未授权的动作，以 `ReplanRequired` 返回协调器。未发出的动作不计费；本次失效不写成永久任务失败。真正的平台失败仍进入既有失败与恢复处理。

所有回退都从当前真实状态继续，保留已经发生的动作成本和永久约束损失，不能恢复到行动前的世界。回退游标须跳过已完成任务，并允许按既有规则恢复仍未满足的正式目标。

### 5.4 对旧资格门槛的具体处理

- 审计主循环、检查、终态恢复、`MustChooseOne()` 和多 `goto` 的风险过滤，防止获批方案在进入执行前又被旧的单任务门槛拒绝。
- 审计 `HasRequestedTask()` 对相反动作的处理。例如存在正式 `close` 目标时，合法的 `open → 取物 → close` 计划可能仍需暂时打开容器。
- 仅对当前获批方案明确授权的计分损失开放执行；对象有效性、容器状态、携带能力、位置与可达性等物理前提继续检查。
- 旧布尔返回链可通过专用重规划信号逐步迁移，但该信号必须穿过所有中间调用，到达协调器后再转换为 `ExecutionOutcome`，不能被通用异常或失败分支吞掉。

## 6. 分批实现与每批验收

| 批次 | 代码工作 | 进入下一批的条件 |
| --- | --- | --- |
| P0：冻结基准 | 保存当前源码／二进制身份、SDK、种子、输入哈希、动作和评分；建立阶段及风险门槛清单 | 可重复运行旧策略，基准材料齐全 |
| P1：原策略与投影重构 | 稳定目标身份、阶段游标、完整原策略调度、投影作用域、虚拟执行时钟 | `off` 动作与基础分不变；模拟零真实 API 调用；现场恢复测试通过 |
| P2：完整决策旁路 | 完整后续评分、节点候选生成、统一预算、`DecisionResult` 与原因日志 | 定向题选对完整方案；不完整基准与候选均不能触发新授权 |
| P3：Stage 1 受控执行 | `CommittedGroup`、动作前授权、后缀复核、重规划结果；接通已支持阶段 | 定向官方题产生真实分数收益；失效和失败用例无越权后续动作 |
| P4：配对验收 | 跑原 60 题及既有高分／压力／恢复题，检查逐题分数、动作、耗时和回退 | 满足第 8 节门槛；确定是否扩大或默认启用 |
| 后续：Stage 2 | 建模相关未知事实、分支感知结果及可靠证据，再扩展真实决策 | 隐藏事实成对测试通过；保留现有大于 24 任务场景保护规则 |

每批应形成独立可回归提交。P1 完成前不接管真实决策；P3 只开放已有完整投影及执行测试覆盖的分支。若旧策略某分支尚不能完整模拟，日志明确说明适用范围回退。

## 7. 必须覆盖的测试

### 7.1 决策收益与评分

1. 单步亏分、完整组增分：执行完整获批组后获得预期收益。
2. 守约组合优于破约组合：避免只对破约侧做组合优化。
3. 新组看似增分，但完整原策略更高：选择原策略。
4. 暂时损失目标后恢复，以及 `open → 操作 → close` 的顺序依赖。
5. 多任务共享一次约束损失；约束奖励资格、重复正式目标、临时任务均正确计分。
6. 多 `goto` 最终位置和尾部移动成本；新 `Stop` 不再进入额外恢复动作。
7. 搜索首层未出现、在后续节点解锁的任务，以及任务数组重排后稳定引用仍正确。

对小规模确定性题建立独立动作级穷举基准，验证最终得分与可执行性；该基准不能复用生产搜索器的候选筛选和评分结论充当期望值。

### 7.2 执行与隔离

1. 正常、异常、超时、嵌套投影后，世界、任务、证据、账本、评分、失败历史和游标一致。
2. 全部模拟路径的真实平台 API 调用数为零；模拟证据不能进入真实世界。
3. 第一步成功后，观测冲突或第二步失败：从真实新状态重规划，无重复计费、误标失败或额外破约动作。
4. 授权外的约束损失被动作前检查拦截；授权内的损失也不能绕过物理前提。
5. 兑现时间不足、CPU 预算耗尽、原策略投影中断、不可模拟分支均正确回退。
6. 原策略各阶段的投影结果与真实旧策略执行相符，包括 `MustChooseOne()`、多 `goto` 和终态恢复。

为动作失败和观测变化扩展现有测试桩，支持按步骤注入返回值与观测内容。Stage 2 真实决策开放前，再补任务内部感知后依赖失效的覆盖。

### 7.3 官方环境验证

先运行少量能区分新旧选择的定向题，确认是实际动作改变带来的收益，再运行全套配对。沿用原方案的 72 个定向实例分组：24 个核心决策实例、24 个隐藏事实配对实例、24 个等价变形实例。Stage 1 首批启用对应确定性部分，其余作为后续 Stage 2 门槛。

原 60 题按 Stage 1／Stage 2、IT／NT 形成 120 组配对；新旧各跑一次，共 240 次正式运行。使用同一 SDK、5000 ms 时限、随机种子 `20260924` 和一致输入哈希。基准为未经本轮决策修改的原 1.6，并额外检查重构后的 `off` 与其一致。

保留既有高分约束、变形压力和纠错恢复测试。仅在计时差异可能影响结论时重复相关题，区分稳定时间退化与单次调度波动。

## 8. 验收指标与交付物

满足以下条件才进入扩大启用评审：

- 至少一类事先定义的目标问题，在官方环境中通过新任务选择获得基础分提升，日志能解释收益来源。
- 原 60 题及既有保护题逐题基础分不下降；不能以总分上涨掩盖个别题退化。
- Stage 2 在本轮保持既有动作与基础分；所有模式无新增超时、未授权破约或真实状态被投影污染。
- 记录并满足单次和累计搜索预算；官方时间奖励没有可复现的持续退化。若基础分提升伴随官方分下降，保留受控模式并单独解释，不自动默认启用。
- 每次接管日志记录：根状态、阶段、完整基准分、停止分、入围方案分、选择理由、承诺后续、授权损失、预算、实际动作以及重规划原因。
