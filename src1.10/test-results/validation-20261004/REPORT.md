# src1.10 开发验证（2026-10-04）

本轮从已提交的 src1.9 独立建立 src1.10。新增联合世界/观测分支/策略树内核；生产路径只接入询问噪声权重修正和离开手持/托盘的证据修正。联合搜索尚未控制真实探测，不属于完整概率模型验收，也不作为比赛替换建议。

普通测试 287/287（含 18 项官方 SDK 检查）通过，4.15 秒。ASan/UBSan 与泄漏检查 269/269 通过，24.47 秒。官方检查包括完整动作状态、真实错误/未知询问回答，以及相同可见集合下不同手持/托盘真相。

测试证明的是已覆盖行为：看见物体不再被当成放下证据，物体槽位排除依据来自具体动作前提/结果，并随修改、撤销及异常撤回失效；概率为 1 不授予事实权限。Stage 1 继承用例原先在 Stage 2 解析后直接切阶段，缺少已知托盘值，现明确提供完整观察的空托盘事实。新 Stage 2 反例仍保持该槽位 UNKNOWN。另一组新增用例补齐直接感知入口和目标位置事实后通过，没有放宽生产判断。

开发期间的构建失败、测试失败和限时搜索波动均保留；包括 SDK 不支持测试中的自定义 ID 字段、误把随机回答域当作去重标签、询问新标签注册遗漏、部分路线缓存改变净值，以及 guarded 限时测试偶发失败。最初证据层诊断的预期失败结果保留；修正后由单元和直接 SDK 反例验证，不用重跑覆盖旧记录。

修复前噪声版本的 10 对先导基础分 +25、官方分 +17、目标 +1，仍有 3 对基础分下降。随后事实修正版的 10 对先导基础分 -500、官方分 -480、目标 -14、约束 +1；该轮同时进行检查构建，基线自身目标从前一轮 94 降至 74，存在并行负载混杂，保留但不作为独立性能结论。

最终采用 src1.9 对 src1.10、14 个历史 ID、IT/NT、5000 ms、两个固定种子、交替 AB/BA 顺序。复用同一对生产二进制，正常默认启动；开始前已结束本轮单测/内存构建，运行中没有代码、SDK 或题目改动。每轮都检查源、输入和 SDK 哈希、执行授权、边界与结果完整性。固定随机种子不固定限时搜索的墙钟前缀，因此仍报告耗时、超时和全部动作差异。
