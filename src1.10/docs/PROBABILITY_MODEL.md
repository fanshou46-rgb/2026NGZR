# src1.9 概率模型开发记录

本版本从已验证的 src1.8 独立复制，分支 `feat/v1.9-observation-model`。日期 2026-10-04。这是持续开发记录，尚未完成全量平台验收；旧版报告只属于各自原版本。

## 目前实现

1. `AskObservationModel` 独立描述 `P(reply | world)`。官方 SDK 的 0.6 正确、0.3 随机、0.1 未知只是分支概率，随机答案也可能碰巧正确。本地随机回答域与真实物理假设域分开，非法 inside 对大物体也可能作为噪声答案出现。
2. 正确处理未覆盖支持：世界中的 `?` 表示未建模位置；观测中的 `*` 聚合本地回答域以外的回答。保留未覆盖随机质量，不把局部候选归一化为完整世界；每个观测模型行和全部回答边际概率应为 1。未覆盖质量目前是显式假设 0.1，尚未校准。
3. belief 支持只读后验和观测边际概率。来自不同真实调用的相同答案可以更新概率；相同事件 ID 重复提交不重复更新。not_known 在此观测假设下不提供位置信息。可信动作/感知确认后同步概率，不由概率确认真实事实。
4. 两步信息规划：为每种回答计算后验，从后验选择一个验证路线，与停止比较，再按回答概率加权。不会在每个隐藏世界选择不同动作后假装机器人有完美信息。
5. 路线成功价值来自原候选规划器的完整投影，失败支路计入验证成本、目标损失与记分约束损失；询问扣除自身成本和耗时。相同后续动作在所有回答下都最优时，询问没有信息收益。
6. 反事实验证只在完整状态快照和 SDK 隔离之后安装。外部位置通过模拟 Sense 确认；柜内位置须经过开柜、Sense、实际语义的 TakeOut 成功反馈确认关系，Sense 本身不确认 INSIDE。结束或异常时恢复全部真实状态。
7. 新回答可能使一次已经观察过的地点值得重查，这种路线单独标记 `requires_new_answer`；未回答前、not_known 与未覆盖回答分支不能使用它。实际执行仍通过原次数、事实变化、约束和 deadline 检查。后验选择的路线仅作为带来源的探测提示。

当前近似公式：

`P(o|b)=Σ_h b(h) O(o|h)`；`b_o(h)=b(h)O(o|h)/P(o|b)`。

`V(b)=max(0, max_route Σ_h b(h)R(h,route))`。

`VOI(Ask)=Σ_o P(o|b)V(b_o, remaining−ask_time) − V(b,remaining) − ask_cost`。

一个可独立核算的例子：先验为 A/B/未覆盖位置各 1/3，询问用 0.6 正确、0.3 在 A/B 随机、0.1 未知（这个数学例子的未覆盖随机质量设为零）。验证路线成功收益 40、失败损失 5，询问成本 2，时间足够。

| 回答 | 回答概率 | 后验选择 | 路线期望价值 |
|---|---:|---|---:|
| A | 0.35 | 验证 A | 27.142857 |
| B | 0.35 | 验证 B | 27.142857 |
| not_known | 0.10 | 原有可用路线 | 10 |
| 本地未覆盖回答 | 0.20 | 停止 | 0 |

问前最优路线价值为 10；问后加权价值为 20，扣除原机会和询问成本，净信息价值为 8。即使回答 A，真实位置为 A 的后验也只是 5/7，仍需验证。这个例子是明确假设下的数学测试，不是赛题实际成功率。

其中路线成功条件、耗时及失败代价仍是模型假设；模型外世界保留概率质量，不能当作路线成功。原普通 Sense 顺序保留；只有询问后已选择的验证提示可提前，仍需重新授权。

## GitHub 参考与已采取的设计

- [pomdp-py 的 value_function](https://github.com/h2r/pomdp-py/blob/main/pomdp_py/algorithms/value_function.py)：借鉴回答边际、Bayes 更新与观测分支的价值求和。本轮以 C++ 自行实现，没有复制运行时代码。
- [DESPOT 的模型接口](https://github.com/AdaCompNUS/despot/blob/API_redesign/include/despot/interface/pomdp.h)：区分 Step/ObsProb 和真实执行，场景状态需要独立复制、回收；本轮先用现有完整快照承载有界场景。
- [POMDPTools 的离散 belief 更新](https://github.com/JuliaPOMDP/POMDPs.jl/blob/master/lib/POMDPTools/src/BeliefUpdaters/discrete.jl)：模型概率、先验、归一化单独检查，不把无法解释的观测伪造为确定状态。旧 POMDPTools 独立仓库已归档，参考的是 POMDPs.jl 内的现有代码。
- [SLOOP](https://github.com/h2r/sloop)：语言描述可作为位置先验。这里只借鉴先验与真实观测的分离；当前输入偏置仍未学习，不把语言提示当作真值。

前三个具体源文件的固定提交、文件 SHA 和永久链接记录在 `test-results/research-20261004/source-audit.json`。没有新增 Python/Julia/DESPOT 部署依赖。

## 首轮不利证据与修正

首轮 16 对平台测试存于 `test-results/pilot-20261004/`，源码快照为 `pilot-source-20261004/`。基础分 6014→3894，原 22/23/24.xml 六对均有目标退化。不能当作新模型通过验收。

暴露的成本错误是 `-int_cost - unsigned_count * 20` 发生无符号下溢，导致很大的正失败价值。已改为浮点负成本，并加入实际规划入口的值域测试；纯 Bayes 数学测试不能覆盖这种集成错误。另发现路线在询问前就受旧地点重复检查拒绝，需要按新答案到达后的可用条件估价。

修正后普通测试 216/216、ASan/UBSan/泄漏检查 215/215 通过。两次六对试验均保留：pilot2 的原 22.xml IT/NT 为基线 15/11、模型 10/10 个目标；pilot3 为基线 15/15、模型 15/10。部分差异是相同动作序列末尾未执行完，不能声称模型已经提高得分。

第一版缓存没有在这些题命中：完整执行签名包括过去动作成本，且 10 ms 内没有完成全部路线。已改为按物理/事实/任务/约束状态缓存已经证明可执行的路线，未完成的路线后续仍可继续搜索，剩余期限每次重新检查。pilot4 的关键题 IT/NT 各命中两次缓存；六对基础分 1210→1383、目标 36→40、官方分 1348→1559，两版均一次超时，Stage 1 动作一致。该结果来自修复 Sense 关系证据前的代码，不等于最终源码收益。

## 真实可见性证据修正

此前单次 Sense 遇到开放/未知柜门，只在弱 inside 提示已经写“在这个柜内”时保留歧义；弱提示写“柜外”则错误确认 INSIDE=NONE。现在只确认观察地点：弱柜外/柜内均保留歧义；当前可信动作关系在未受到反证时保留，旧关系指向异地柜则清理为未知。

新增 `filterVisibility` 消费真实 Sense 的出现/未出现结果。柜内位置只有在柜地点与已开启状态都可信且仍未看到物体时才排除；关闭/未知柜门保留遮挡可能。正向观察排除其它外部地点和已知不可能可见的柜内位置。残余世界仍保留，不以未知柜门的任意概率做重复 Bayes 加权。这是确定的可见性矛盾过滤，不是已校准的完整观测似然。Stage 1 和反事实投影不更新这个真实观察 belief。

普通测试 226/226、ASan/UBSan/泄漏检查 225/225 通过。保留两次 sanitizer 的限时搜索测试失败及原测试重跑通过记录：这些断言错误要求任何机器负载下限时搜索都必须成功。测试现在独立证明改进路线、检查限时回退无动作且状态恢复，动作失败用已经授权的完整路线验证；没有放宽生产搜索上限。改写测试时首次手写路线顺序不满足空手关闭柜门的条件，已按实际动作前提修正，失败记录也保留。

## 扩大测试发现的确定性退化

真实可见性过滤后，14 道历史题 × IT/NT × 两种子共 56 对中，基础分分别 11961→10200、12874→10254；目标分别 282→230、309→233。关键 22/23/24.xml 从 5–15 个目标降到 1 个。完整保留在 `development-seed20260924/` 和 `development-seed20260925/`；对应产品快照为 `pre-known-sense-source-20261004/`。不能用先前 pilot4 的收益替代这些结果。

移除不存在目标的位置后，模型不再能借“目标恰好与源物体同地”的便宜假设通过。定位到实际集成问题：`BuildTaskGroupPlan` 在模拟后先恢复现场，再以恢复后的未知绑定判断未来路线的资格。在大题的 risk/two-loss 门槛下，这会拒绝观察之后本来可以规划的路径。修正为在隔离场景完成验证、尚未执行任务时保存未来绑定的资格；普通规划仍读现场事实，不依据任务模拟成功之后的事实绕过门槛。

最初“额外 Sense 是主因”的诊断假设未通过动作级复现，没有采用放开所有额外感知的修改；这次失败诊断也保留。新的四个边界测试中，修复前只有“未来已验证路线被拒绝”的用例失败；未知其它物体、未验证 inside 和真实执行入口都保持原门槛。修正后的普通测试 232/232、ASan/UBSan/泄漏检查 231/231 通过。另为问后验证预留探测成本，缓存命中也重新检查剩余探测预算；过去动作成本虽可从边际收益中抵消，累计授权预算却不能抵消。

## 完成验收还需要什么

- 数学检查：观测行/回答边际归一化，独立联合概率枚举验证价值；无信息/已知世界/时间不足时不应高估询问。
- 权限检查：反事实投影零 SDK 调用、真实 canonical/任务/账本/belief 不变；错误、重复、未知答案仍需真实验证。
- 模型完整性：目前目标之外的物体位置、柜门及手持/托盘未知状态未形成联合场景。完整续规划里若出现额外未建模感知/询问，路线仍视为不完整。这会低估探索价值，需继续实现独立隐藏场景和局部观测，不能把不完整估值当作已经证明无收益。
- 实测：修正后的开发对照已完成 14 题两种子与内存检查，完整历史输入和 comprehensive 尚待验收。必须同时报告 G/C/K、基础分、官方分、时间、超时和退化。
- 校准：用后来真实验证的反馈训练回答/可见性/耗时模型，未验证样本不标为正确；留出题和种子检查校准及选择偏差。

目标保持为“继续完善概率模型”，本记录没有把单元测试通过定义成目标完成。
