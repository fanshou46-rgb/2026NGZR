# 1.7.5：退化定位与放置证据恢复（开发验证）

本版继承 1.7.4，保留 1.7.2—1.7.4。旧版四版本审计见根目录 `docs/AUDIT_1.7.2_1.7.4.md`；本轮结果最终写入 `validation/review175-20261004/REPORT.md`。

## 为什么 1.7.4 变低

旧审计 96 次对照：1.7.3 基础分 11456 / 376 个目标；1.7.4 基础分 10229 / 335 个目标。基础分下降 1227，目标少 41；闭柜约束一组下降 608 分，多个容器同地一组下降 529 分。1.7.2 到 1.7.3 基础分上升 154，下降并非每一版都发生。

1.7.4 修正了“看见物品就认为不在托盘上”的错误。修正是必要的，但候选规划缺少补充验证路径：TakeOut→Move→PutDown 后仍可能 tray=A，终态只能 UNKNOWN，候选获得不了送达收益。闭柜题在打开柜门损失 20 分的同时，又拿不到后续目标的确定收益，于是选择只移动/感知后停下。

同地多容器的 Sense 还保留了更早的单容器假设：只记最后一个容器，并可能清掉其它柜内提示，把目标改成地面/未知关系，引发重复 PickUp 与取错容器。官方 Sense 只给 ID 集合，at 与 inside 独立，既不证明柜外，也不证明槽位排除。

终态与输入资格还有不必要的 inside 前提：SDK 的 pickup/putdown/puton/give 等由槽位及地点决定，不能因为柜内关系尚 UNKNOWN 就一概拒绝。

## 这版具体增加/修复

- `ConfirmOutsidePlacement`：放置后仍不知道是否在托盘上时，先 PickUp，再 PutDown；PickUp 因 tray=A 失败时转 FromPlate→PutDown。只依据真实反馈写事实，不把弱初始空托盘升级为真。仅在必要时走验证路径，实际分支最长 3 个动作，执行前保留 300ms 与原安全余量。候选投影仍沿当前假设分支估算，真实失败转移单独记账；尚非完整联合概率策略。
- Sense 保留 inside 弱提示与已验证关系，交给动作验证；取消可见 ID 对 inside=NONE 的推断。当前地点缺失物品的检查仍保留原先逻辑，尚需更广泛的独立关系复核。
- 放下/送达等终态不再要求无关柜内事实；输入资格只为 putin/takeout 保留柜内前提，存储、动作权限、约束交换与截止时间仍走原门槛。
- 手持/托盘赋值不再隐式清掉另一个槽位，取消官方允许双槽同物时的错误拒绝。合法 ToPlate/FromPlate 仍由对应动作明确修改槽位。
- 独立概率内核 `JointWorld.inside` 从单编号变成关系集合。PutIn 添加一条边，TakeOut 只删除目标边；允许 SDK 合法双槽同物。搜索只将回答顺序未覆盖异常标成覆盖缺口，其它模型异常正常暴露。
- 加入真实 SDK 的多个 inside、双槽及三种托盘真相对照。294 项普通与官方直接检查通过；既有测试中的不实语义断言按 SDK 修正并保留失败日志，未通过调低目标断言掩盖算法失败。
- 12 道独立扩展题：四类结构、每类三个编号/地点/任务顺序排列，每题 6 目标，包含更长搬运路线、三个容器同地、同物体托盘与柜内并存、多个目的地及重叠终态目标。设计不读规划器结果；预检修正 XML、合法词表与官方 5 秒预算后正式冻结。所有草稿及失败记录归档。

## 尚未解决的边界与下一步

生产 `SmallObject::inside` 仍是单值，PickUp/PutDown 等继承动作仍会清除柜内缓存；SDK 允许 at 与多条 inside 共存，生产层尚未完全修复这个语义缺口。概率内核的关系集合没有自动替换生产事实层。不能把内核测试通过解释为生产关系已完全正确。

下一步先为生产事实层建立逐容器的真/假/未知关系，保证事务回滚和约束账本一致；用已确认空手下的 FromPlate 失败学习 tray≠A，可以减少本版额外 PickUp/PutDown 费用。随后把联合先验、未覆盖质量、公开反馈分支与真实记分接入 Probe，比较完整路径的预期净收益。概率回答仍是弱线索，需后来未被动作改变的 Sense/动作结果作为校准标签。对未来新题和完整比赛题复跑，逐题保留基础分、官方分、G/C/K、时间和退化。

复制目录中的旧文档记录其原版本实验；以本说明和根目录本轮报告作为 1.7.5 当前验证入口。未宣称已完成联合规划生产接入。

## 本轮重新核对的开源参考

[pomdp-py Agent / Environment 接口](https://github.com/h2r/pomdp-py/blob/bd0e4392247aebfe9a95b449275237dcc25e7737/pomdp_py/framework/basics.pyx) 将机器人的信念与环境真相分开；当前联合内核继续遵守这个边界。下一轮不能用 SDK 隐藏状态给生产先验赋值。

[POMDPTools 离散更新](https://github.com/JuliaPOMDP/POMDPs.jl/blob/d970a36d6e41b7d6baa8377ce0426c7282bc5025/lib/POMDPTools/src/BeliefUpdaters/discrete.jl) 按转移及观察概率加权，再归一化；观察总概率为零时显式报错。此处的设计借鉴是：动作失败也有信息价值，而不可能反馈应触发覆盖诊断，不能被广义异常捕获伪装成普通回答顺序缺口。本轮未复制外部源代码或引入新运行时。

### 与原分数下降相关、仍需继续处理的具体路径

`ProjectVerification` 仍存在模拟 Sense 将无柜地点的 inside=NONE 标记已验证的继承路径；它只影响候选估价，不直接修改真实机器人，但会让模拟与生产的证据门槛不一致。真实 Sense 可见柜内物品时，生产位置层仍混用了“可见地点”与“SDK 显式 at”。这些也是联合事实层下一轮要拆开的边界。

未知柜门状态下的询问路线，目前 `ProjectVerification` 要求已确认柜门和空手，可能在真实还有充足时间时拒绝构造完整路线。本版对照保留这种停滞，不用提高概率参数或恢复错误的 Sense 事实来补分。
