## 这几版的实际机器人流程

1. 读取题目和环境，绑定物体，检查目标与约束。Stage 2 的初始位置、询问回答属于需要核实的线索。
2. 通过事实层查询目前确实知道什么；通过概率层保存尚未确认的位置可能性。两层不应互相冒充。
3. 普通规划投影候选动作，比较终态目标、约束损失、动作成本和剩余时间；已确认条件下尝试多任务组合。
4. 有合适的普通任务就执行。每次真实动作或感知反馈改变状态后，重新判断资格和剩余收益。
5. 普通任务无法推进时，Probe 枚举有限的感知、移动感知、开柜感知和询问候选。
6. 1.7.2 主要以位置概率和启发式机会值评价；1.7.3 / 1.7.4 对询问进一步展开“收到这个回答之后，走哪条验证路线”。回答不直接授予已确认事实。
7. 检查探索次数、累计成本、约束风险、重复观察和截止时间，授权后才执行；得到反馈后回到普通规划。
8. 没有值得执行的合法候选，或者剩余时间不足时停止；退出前等待规划线程结束，再清理状态。

1.7.4 的联合树目前位于上述流程之外。它能在测试提供的多个完整世界之间推演公开反馈，但还没有自动构造真实世界先验，也没有替换步骤 5—7。

## 已确认的错误

### P1：成功拿起、放下以及特定感知会错误清除柜内关系

官方 SDK 接受物体同时有 `at(A,L)` 与 `inside(A,C)`。`at` 和 `inside` 是独立关系；成功 PickUp、PutDown 不会自动删除 inside。关闭柜门也不会遮住具有独立 at 事实的物体。

生产 `rdfw.cpp` 的 PickUp / PutDown、SetHold / SetPlate 以及部分 Sense 分支仍把这些关系当成互斥状态。独立反例给实际 RDFW 提供官方动作反馈，得到：

| 反馈序列 | RDFW 的“取出杯子”终态 | 官方 SDK 的目标得分 | 官方基础分 |
|---|---|---:|---:|
| Close → Sense | SATISFIED | 0 | -3 |
| PickUp | SATISFIED | 0 | -2 |
| PickUp → PutDown | SATISFIED | 0 | -4 |

负分只有动作成本；柜内关系仍在，目标没有完成。反例程序返回成功表示“成功复现错误”，不表示产品通过正确性检查。代码见 `../tools/review_172_174/semantic_counterexamples.cpp`，实测见 `../validation/review-20261004/semantics/results-v2.json`。

以上独立 SDK 运行针对 1.7.4。前版继承点通过源码逐版对比定位，并未把前版未运行的反例称为实测。

这一类假设来自继承代码；1.7.4 修正的是“是否还在手/托盘”证据，没有同时修正全部柜内关系。不要把所有问题归咎于新概率模块，也不能因旧版分高就恢复这些错误事实。

第一个感知诊断的初次尝试没有复现：Stage 2 中仅提供初始 closed 提示并不足以确认柜门，代码保留了歧义。随后改为真实 Close 成功再 Sense，才复现上述错误；初次失败记录保留。

### P2：联合模型的支持范围不能保持合法动作后的状态

`JointWorld::validate` 接受“物体在托盘，同时 inside 柜子”的输入。官方 SDK 允许此时 TakeOut 成功，并留下同一个物体同时在 hand 和 plate 的状态；联合模型完成转移后却因禁止同物体占两个槽位而抛异常。

因此，“所有通过 validate 的世界都能按官方动作规则继续推演”不成立。当前内核不在生产决策中，不能据此宣称真实机器人会因此崩溃。接入之前必须扩大状态表示，或者在入口明确拒绝这一支持范围，并让搜索报告准确的未覆盖原因。入口拒绝只能是暂时的降级保护；完整模型仍需覆盖这些合法动作及其结果。

补充直接 SDK 反例也发现：具有 at 和 inside(C1) 的物品经 PickUp→Move→PutIn(C2)，SDK 保留 inside(C1) 并增加 inside(C2)；JointWorld 只有一个 inside 字段，静默丢掉 C1。因此支持闭合既可能抛异常，也可能得到错误终态。代码见 `../tools/review_joint_multi_inside.cpp`，结果见 `../validation/review-20261004/semantics/results-multi.json`。

另有诊断问题：搜索把捕获到的多种 `logic_error` 都写成 `unmodeled_answer_order`，这会把物理转移缺口误报为回答顺序问题。不能靠捕获异常后换一个名字，就认为模型已经覆盖。

### 复核工具与版本标识

1. 原 1.10 的比较脚本默认基线仍为 1.8，而非直接前版 1.9。历史最终对照显式指定了基线，因此已有报告不因此失效；默认入口应修正为新编号 1.7.3。
2. 原 1.10 启动日志仍报 1.9。目录命名不能解决日志混淆，需同步版本标签，并记录标签变更前后的源码对应关系。
3. 旧比较汇总有把缺失评分当 0 相加的做法。新复核单独记录缺失、崩溃、SDK 超时和外部超时；缺失结果不能当成正常低分参加配对结论。本轮 1.7.1 的一次崩溃使服务器未输出动作与评分，继承提取器仍从临时 ASP 目标数和空动作列表计算出 120；该值不是有效基础分。原始字段保留，最终汇总与 CSV 明确排除该格，不把它填成 0 或 120。
4. 模型说明混用了修正前 268 项和修正后 287 项测试数，本轮已经明确标为不同阶段的历史记录。

## 新题如何避免继续围着旧题调参

新增 `../题目/generalization_20261004/`：24 道题、12 个情形族，每族两个独立编号、位置和指令顺序排列。前 8 族用于开发复核，后 4 族预先指定为结构留出组；这一轮对两组都不调参数、不修生产决策代码。

覆盖完整已知搬运、缺失位置、错误位置、隐藏闭柜内容、错误柜子、托盘占用、手持占用、闭柜约束交换、同址多柜、独立 at/inside、同类不同颜色物品、互相冲突的终态目标。

同址多柜与独立 at/inside 单独列为 SDK 语义压力题。官方模拟器能执行这些题，不代表它们在正式赛题中的出现概率；普通题与压力题必须分开报告。每题有一条独立参考动作路径，由官方 SDK 验证实际得分。这只是可行解证据，不声称全局最优。

固定设计种子 714203，运行种子 2026100401 / 2026100402。计划矩阵为 24 × 4 版本 × 2 种子 × IT/NT = 384 次运行，另有 48 次参考路径验证。每格保留题目哈希、二进制哈希、原始动作、官方最终状态、分数和时间；串行轮换版本顺序，不在限时对照期间并行构建。

这是根据模型边界设计的定向复核，不是设计者完全不了解代码的盲测。每题只有 4—5 个目标，不能代替正式比赛规模的任务量和搜索压力验证。

这些题在此次生成后就冻结，不能拿本轮结果继续选门槛，再称同一批题为“未见测试集”。24 题也不足以证明全面泛化，更不能用几个随机种子代替独立情形数量。

## 后续优化顺序

1. **先修事实语义。** 把显式位置、柜内关系、hand、plate 独立建模；逐动作核对 SDK 的保留、增加、删除关系。把本轮三个误报反例转成“禁止错误确认”的回归测试，再用新版本承载修复。
2. **补齐模型支持与异常分类。** 保证支持集对合法动作闭合；没有覆盖的世界保留残余质量，反馈无法解释时重新生成候选世界。不得把删除真实可能性后的概率 1 当成确定事实。失败反馈也可以提供信息，但必须先确认其它失败原因已排除；例如已经确认空手时，FromPlate(A) 失败才能据官方前提排除 A 在托盘。
3. **连接完整收益。** 联合模型调用统一终态评分和约束历史，计算整条合法路径的期望收益。未知托盘情况下，路径可能值得尝试，但还不能报告“确定已经完成”；这两个量分别使用。
4. **先旁路比较，再接执行。** 同一机器人状态下记录新模型想选什么、为什么、预期收益和计算时间；先不执行其动作。检查不会读取隐藏真相、预算超限和支持不足后，再通过现有授权层接入。
5. **校准概率与时间。** 只用后来被独立感知/动作验证、且中间没有被搬动的标签校准 Ask。不能用 Ask 的回答给 Ask 自己打标签，也不能用自身猜测当真值。分别评估地点/柜子回答、错误/未知回答，记录 Brier 分数或对数损失和可靠性分箱。
6. **扩大外部测试。** 按情形族划分开发、校准、最终留出集；加入跨布局、数量、目标冲突和噪声强度变化。每次算法升级报告配对基础分、官方分、目标、约束、动作成本、耗时、超时和所有退化；检查收益是否只来自少数家族。

GitHub 中可继续借鉴 pomdp-py 的 Agent/Environment 分离、DESPOT 的场景与公开观测接口、POMDPTools 的显式贝叶斯更新。此前已阅读的固定来源见 `../src1.7.4/docs/JOINT_MODEL.md`。这些项目提供结构参考，不能代替本比赛 SDK 的语义验证。

本轮是审计与独立评估，不把尚未修复的生产语义问题藏进版本重命名，也不将实验内核宣传为已上线能力。

## 本轮新题结果

完整 384 次对照与 48 次参考验证已经完成。1.7.2→1.7.3：96 对基础分 +154、G +2；1.7.3→1.7.4：96 对基础分 -1227、官方分 -861、G -41、C +8、K -253。普通题与结构留出组都退化。1.7.1 有一次退出崩溃且缺失评分，涉及它的对照只使用 95 对，不填零。具体时间、超时、逐题退化、源码冻结范围见 [独立新题报告](../validation/review-20261004/REPORT.md)。
