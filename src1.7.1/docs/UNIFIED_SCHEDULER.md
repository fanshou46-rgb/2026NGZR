# src1.7.1：继承的统一 scheduler 与 Probe 接入

本文件保留 src1.7 的冻结流程说明。src1.7.1 的唯一新决策入口位于真实 Stage 2
无合格正收益 task 的分支，详见 [PROBE_LAYER.md](PROBE_LAYER.md)。
Stage 1、shadow 和 greedy continuation 禁用 Probe；正收益 Multi-GOTO 尾部优先。
MustChooseOne 已替换为只读 proposal / 日志包装器，不具有执行权。
本次构建、复跑和验收以 PROBE_LAYER / RELEASE_1.7.1 为准，下面的 1.7 命令与报告是历史记录。

## src1.7 原说明

基于仓库 HEAD `f3088813` 时的最新源码目录 `src1.6.7-200ms`。
`src1.7` 在创建前不存在。所有旧版本保持原样。
正常启动只有一个策略，不需要策略参数或 `RDFW_TASK_GROUP_MODE`；旧环境变量被忽略。
Stage 2 的证据优先级过滤仍保留，不能把规划假设记为已验证状态。

## 决策与执行

每轮从真实状态更新任务、生成完整单任务投影、检查资格/完整性/预算/单任务约束交换，
在合格且边际基础分为正的候选中选最大值。相同收益优先预计时间更短，再按输入任务稳定 ID。
guarded 在同一轮内部自动尝试；模拟中的 greedy 调度不调用 guarded。
执行成功或失败之后丢弃整轮候选，从反馈后的状态重新生成。
没有正收益单任务时也先尝试支持范围内的任务组搜索。

guarded 保留 Stage 1、非 Multi-GOTO 的支持边界；Stage 2 或时间不足自动使用 greedy。
每次最多 25 ms，整道题累计最多 100 ms（包含参考方案、搜索、后续方案、授权投影）。
同时使用既有 5000 ms 总期限、普通计划 200 ms 安全余量和 Multi-GOTO 100 ms 尾部预留。
候选生成以及所有计算均消耗总期限的真实墙钟时间。

比较使用同一初态和固定剩余时间，包含立即停止、完整 greedy 后续、任务组后停止、
任务组后继续同一套 greedy。只有挑战方案的基础分下界严格超过基准/停止的上界才替换。
不完整、含未支持观测、超时、同分或证据区间重叠时回退。
任务组后继续 greedy 若获选，绑定经过验证的完整任务和动作序列，包含该 greedy 后续；
执行中逐动作检查状态签名、动作参数、时间和约束损失范围。
失败或偏离立即放弃剩余序列，从真实反馈状态重新决策。

普通循环已经包含终态修复，不再按索引增加一个“检查阶段”或 MustChooseOne 兜底主循环。
旧 MustChooseOne 按风险/索引选择并可执行 `eligible=false` 的任务，这与本次要求的资格筛选不符，
因此生产流程不再调用它；能重新获得资格的修复任务由每轮 RefreshTaskStates 和完整投影处理。
多个 GOTO 先延后到既有聚合尾部，尾部后用同一循环检查必要修复。
明确停止后不运行聚合或恢复。

## 标识、失败与模拟

`Instruction.stable_id` 是优化前的输入展开序号；`task_index` 是优化后向量索引。
终态目标数组、失败记录和约束关联始终使用后者；同收益排序使用前者。
排序先按既有行为优先级，再分隔 takeout 子组，再以完整容器键和稳定 ID 排序。
空 Y/null Y 使用统一键，避免混合 takeout/putdown 的比较器环及等价关系不传递。

失败任务在同一 `world_revision` 禁止再次尝试；状态变化后可重试，每任务至多 3 次，
整个问题至多 `6 * tasks.size() + 8` 次决策执行。
无进展签名不包含成本、版本递增、完成计数和任务标记，避免把账面更新误当物理进展。

投影恢复任务标记、对象及证据来源、约束账本、失败版本、尝试计数、调度计数、动作成本、
执行反馈及执行保护状态。嵌套候选扣除已投影前缀动作时间，不会重置整个方案可用时间。
候选 ID 是诊断序列；搜索耗时和超时控制标记保留用于限制真实搜索预算。
基础分与历史约束资格未修改：`40G + 20 * I(G>0) * C - K`，目标按终态，约束按历史资格。
`G>0` 作用于整道题终态，无需每个子计划新增目标。
