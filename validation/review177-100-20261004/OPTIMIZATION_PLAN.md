# 1.7.7 缺点与优化计划

本轮只交付计划，不修改比赛策略、不创建1.7.8。以下顺序依据冻结代码和可复查轨迹制定；收益必须在独立副本中验证，不能把建议写成已经改善的成绩。

## 第一阶段：恢复确定信息下的任务组合能力

**P0：先控制搜索预算的行为波动。** 三个独立种子的270组新Stage2配对中，三个消融与原版的动作及G/C/K/base全部一致；Stage1却分别有30/38/32格动作不同，差异不能当作模型收益。重复0403时，原1.7.7有11/180格动作变化、10格G变化，均在Stage1；两版1.6.7的180格动作和G全部一致。先用可复现的节点预算、完整候选收据及墙钟保护检查搜索截止位置，再谈概率排名；重复轮不作为独立样本。

**P0：保留搜索截止前已经验证的可行组合。**

- 触发：单任务分别会暂时破坏已完成目标或约束，完整组合却能恢复并带来净收益；搜索达到25ms后整体回退，贪心没有正收益单任务，于是提前停止。
- 原因：`src1.7.7/rdfw.cpp:2023`在读取`best_safe/best_broken`之前，以`budget_exhausted/projection_failed/expired`丢弃整轮结果；后面的继续路线超时也会丢弃已验证的独立前缀。搜索不完整不等于每个已完成候选都不合法。
- 修法：分别保存“完整投影并通过证据/约束/终态/期限检查的候选”与“尚未完成的搜索”；截止时可提交前者。任何依赖后续恢复才能盈利的前缀，仍须绑定已验证的完整恢复路线。不得提交半个候选或降低执行事实门槛。
- 验收：新题A01-02-s1及B01/C03/C05反事实对，增加精确节点预算的确定性检查：在找到盈利组合后截止，应保留该组合；在恢复尚未验证时截止，应拒绝。同源码多次运行分别记录搜索节点、已验证候选、预算耗尽点、实际G/C/K和截止。完整71输入、52结构题不能出现未经解释的目标/基础分退化。

**P0：让未确认任务只阻断自身，不阻断所有已确认组合。**

- 触发：Stage2同时有位置未知的任务和已确认的运输/关门/终点任务。
- 原因：`rdfw.cpp:1995–2009`先要求手和托盘全部已确认，再检查所有根候选；任一根含观察或未知事实，就拒绝整轮组合。前三个种子的270格新Stage2中，`unverified_storage`出现618次，实际是比未知任务根更早的拦截点。
- 修法：按每个候选及被选组合的真实事实依赖计算资格，建立已确认支持的子集；不使用槽位的动作仍须证明对可能携带物与相关约束安全，不能简单跳过槽位检查。需要腾手/托盘的组合先构造可靠反馈验证；只有覆盖所有可能槽位对象的有条件排除，才可确认空槽。未知根进入观察分支，已确认且安全的子集可独立组合。
- 验收：A01/A02 Stage2公开证据逐步补齐；未知根存在时，已确认子集可执行；加入一个无关未知任务不得改变已确认组合资格。多父inside、独立at及手/托盘共存的旧回归全部保留。

## 第二阶段：补完整的反馈和恢复路线

**P1：打通未知槽位—移动约束—感知的闭环。** `probe_layer.cpp:343–385`在未知携带关系可能影响near等约束时拒绝移动观察，概率大小无法替代安全证据。前三种子270格中，移动观察`constraint_safety_unknown`拒绝1386次，四臂全部相同；Probe层执行48次额外当前地点Sense，SDK全程Sense450次、Ask0次。应先设计不会破坏相关约束的槽位反馈/局部验证，记录支持与排除，再评估跨地点探测。验收包括“实际空托盘但初态未知”“托盘有受near保护物”“同物手/托盘共存”；未知不直接确认为空，受保护物不能因移动丢失约束。

**P1：把探测、任务完成及返回终点作为一个策略估价。**

- 触发：当前已满足goto，离开后能找到目标并完成任务，最后能回到原终点；现在只扣确定损失而没有返回路线，候选被过滤。
- 原因：`probe_layer.cpp:500–511`正确计入40分终态损失，但继续成本和机会收益仍是部分启发式；`139–145`的概率仅指至少一个相关ID可见，不能保证完成全部潜在目标。
- 修法：从公开假设构造Sense反馈分支，逐分支模拟执行、失败费用、被破坏目标、历史约束以及回程，计算最终SDK基础分与期限；未覆盖质量单列。先用有界完整路线，避免直接给当前启发式提高权重。
- 验收：A04/A05/C01/D02配对，分别有“可回程且净增益”“回程超时”“不可恢复约束”三个用例。估价包括所有动作K及真实终态损失；没有可靠回程时仍应保守停止。

**P1：未知柜门和不确定拿取需要成功/失败分支。**

- 触发：有容器位置线索但门状态未知，或可见物没有独立at；当前路线不生成或被拒绝。
- 原因：`answer_planning.cpp:33–37`拒绝未知父容器/柜门及非空手验证路线；`probe_layer.cpp:436–440`只为确认关闭且位置已知的柜生成开柜观察。严格事实语义是必要修正，缺的是合规反馈策略。
- 修法：构造腾手、验证、实际动作、失败学习与恢复的分支；成功只确认SDK反馈支持的事实，失败仅作有条件排除，不清除无关inside、独立at或另一槽。动作尝试照常收费。
- 验收：已有52题中的未知门、双父、托盘与inside、独立at族；新B02/B03/C02。同时覆盖动作成功、失败、同物双槽和不同物占槽；逐步对齐SDK状态与内部判定，不允许靠错误清边提高目标数。

**P1：证据变化后有条件恢复任务重试资格。**

- 触发：早期候选因错误位置失败，随后Sense/Ask获得新支持，但任务仍受固定三次尝试上限影响。
- 原因：`probe_layer.cpp:150–156`及任务重试计数按任务次数限制；计数与事实版本、已排除路径的关系需要逐轨迹核对。
- 修法：记录任务—证据版本—失败原因—已尝试路径；只有新增相关证据能重新授权曾失败路径，公共次数/时间/费用限额继续有效。相同证据下不盲重试。
- 验收：A02/A03/B02的错误线索与噪声询问，加入“新证据允许一次新路径”和“重复同一回答不得重置限额”的配对检查。

## 第三阶段：让概率确实服务于可执行收益

**P2：按完整分支价值比较物理观察路线。**

- 触发：两个可执行观察点的成功机会、目标收益与费用不同，当前物理Probe按事实数/类型等顺序选取。
- 原因：`probe_layer.cpp:514–529`只有AskLoc按expected_gain排序；物理观察的概率主要用于执行过滤。门槛变化可能有局部收益，但不能据此宣称全局路线优化。
- 修法：在第二阶段完整收益成立后，统一比较物理Sense、Open+Sense和Ask+验证；保留稳定平票和必要感知。以同一公开前缀的候选值、资格和首个有效动作分叉验证模型作用。
- 验收：六臂消融继续保持唯一变化；按Stage2/题族报告成组区间、G/base/formal及耗时。只有稳定收益并能定位概率引起的有效决策变化，才提升模型地位。正式分涨而G降单列为取舍。

**P2：持久联合后验和校准分开推进。**

- 触发：多容器/槽位/柜门相关且支持超过32个局部场景，残余质量较大；问答先验与真实频率不一致。
- 原因：`visibility_forecast.cpp:6–79`每次构造局部场景，覆盖折扣0.75/0.5及问答0.6/0.3/0.1为冻结开发假设；未持续表达全部相关动作后验。
- 修法：先实现受控规模的联合状态与动作反馈更新，明确支持覆盖及残余；另用有标签的执行反馈校准先验/问答/可见性。校准集、选择策略和留出集分开，未执行候选不补造标签。
- 验收：事件重复不重复更新，硬确认/硬排除不可被弱回答覆盖；联合支持包含SDK合法多关系。报告选中候选的偏差与覆盖率；在新留出结构题做概率中性/no_ask/legacy_visibility对照。

## 第四阶段：耗时和输入边界

**P2：分清模型CPU、SDK调用与剩余期限。**

- 触发：同种子重复因25ms墙钟搜索产生不同动作，或估时不足造成5000ms硬截止。
- 原因：搜索墙钟预算、固定动作估计与SDK实际耗时共同影响决策；`probe_layer.cpp:475–484`重复构造同一目标/地点可见性预测。
- 修法：按事实版本和目标/地点缓存可见性；记录模型CPU、候选搜索、每种SDK调用的独立耗时及保守分位数。搜索用稳定节点预算辅助墙钟上限，动作总期限仍以真实墙钟执行。
- 验收：重复0403轮用于运行波动而非独立样本；检查同输入同种子动作一致率、预留误差、SDK截止与外部超时，缓存前后概率和资格完全一致。

**P1（输入安全）：明确拒绝非法报文及IT/NT冲突。**

- 触发：错误字段/指令或两个表示含不同目标，SDK仍可能以某一表示执行。
- 修法：题库/运行器层在进入SDK前验证两种表示一致性；机器人只验证自己实际收到的报文及指令，不读取另一表示或作者真值。对SDK已经接受的坏输入也记录机器人是否执行。格式/语义错误的处理单列，不计入能力分。
- 验收：本轮10道非法题逐项匹配预期原因、实际拒绝层和是否执行动作；合法90题及历史输入兼容性另测，不能因防护误拒合法题。

## 执行顺序与通过条件

按“搜索结果保留 → 已确认子集 → 完整恢复与反馈 → 概率路线价值 → 校准与耗时”逐项推进，每次只有一个可解释变化。原1.6.7、1.6.7-200ms和1.7.7继续冻结，所有试验先在独立副本完成。当前100题已经用于本轮对照，后续成为回归集；新优化的泛化结论需要另设未看过成绩的留出结构题。

每次验收同时给出实际G、C、K、基础分、SDK原始分、封顶正式分、失败动作和截止；保留所有退化。基础分缺失保持缺失，正式分另给缺失按零汇总。不能以总体正式分提高替代目标完成能力，也不能用恢复错误事实语义来补分。
