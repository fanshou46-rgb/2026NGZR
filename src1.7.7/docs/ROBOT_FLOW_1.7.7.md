# 1.7.7 从收到题目到结束的实际决策

以下对应本版生产代码。概率模型参与观察机会评估；完整联合行动策略树仍是独立内核。

1. **开始新题。** 重置时间、动作费用、约束记账、探索记录、证据及缓存。主线程控制规划线程生命周期。
2. **读取公开环境。** 解析机器人、物体、地点、手、托盘、柜门及逐容器关系。Stage 1 可确认实际输入；Stage 2 初始描述只作提示。本版把独立 `at` 与观察得到的路线位置分开：不知道、确认没有、确认地点三种状态。隐藏环境和参考路径不输入机器人。
3. **读取目标与约束。** IT 解析结构指令，NT 解析自然语言；按物体属性及 ID 绑定，隔离非法条目。目标是否完成看当前证据，不看执行标记。
4. **更新事实资格。** 约束推导须保留依赖；初始提示、询问答案不覆盖强动作证据。槽位或容器的一条正边不自动否定另一条正边。
5. **判断是否停止。** 所有目标确认完成、剩余时间不足或截止到达则退出。多个 goto 暂缓到尾部路线评价，不能仅靠曾经到过某地认定最终完成。
6. **模拟单任务。** 保存世界，模拟完整路线，计算目标和约束得失、真实动作费用及耗时估计，然后恢复。恢复包括独立 at、逐容器关系、槽位排除、概率与缓存。模拟不调用执行器；只选择证据合格、收益为正且预算允许的候选。
7. **比较任务组。** Guard 自动检查有限组合能否比单任务更好。需要尚未建模的观察分支、未知动作前提或无法完整恢复目标的组合仍可能被拒绝。
8. **实际执行。** 每次尝试均计费，包括失败。成功才更新动作证明：TakeOut 只删除指定 inside，PutIn 只增加指定 inside 并移除独立 at；拿放及托盘转移保留其它 inside。携带移动更新已确认槽位物的 at。失败不给出成功事实；事务异常撤销本地未提交状态。
9. **确认送达。** PutDown 不证明托盘不是同一物品。需要时，在确认空手下用 FromPlate：成功后 PutDown，失败只证明托盘不是目标。终态及零动作捷径检查独立 at 与槽位；确认没有 at 时，开柜可见不能冒充已送达。
10. **停滞时列出 Probe。** 枚举原地 Sense、MoveSense、OpenSense、AskLoc；检查公开前提、相关未知、约束风险、重复反馈、累计探索预算及时间。MustChooseOne 不执行随机任务。
11. **估计物理观察概率。** 每个目标最多构造 32 个局部联合场景，保留 at、全部已确认父边、槽位和柜门，用仍有效的公开 Sense 出现/缺失条件化。可见性是各原因的并集；遗漏、未知及不合法支持进入 residual，输出上下界。候选使用下界，不把未覆盖质量分给已知场景制造确定答案。
12. **估计询问与收益。** 询问仍采用噪声回答分支和回答后验证路线。多个已确认正确答案的选择顺序未知时明确拒绝这项模型估价。物理探索计入动作、继续费用、时间、约束及已完成目标损失；离开 goto 地点先扣 40 分，没有完整返回路线就不假设必定恢复。当前机会值仍是启发式，不能等同完成全部任务的概率或完整收益下界。
13. **接收反馈并重规划。** Sense 的 ID 不能证明唯一位置、柜外或不在槽位；Ask 也可能错误。公开证据更新资格及概率后重新比较候选。支持全部不匹配时保留未知并记录，而不是选一个“必须正确”的答案。重复提问或只增加世界版本不算有效信息。
14. **结束与核分。** 无合法有收益任务及可执行 Probe，或剩余时间不够时停止。内部报告 G/C/K/base，官方模拟器按隐藏真实终态评分；两者逐格比较，全部高报、低报、失败及硬截止都保留。

代码入口：主循环与动作在 `rdfw.cpp`；关系在 `containment.cpp`；事实在 `canonical_state.cpp`；终态在 `terminal_checker.cpp`；观察候选在 `probe_layer.cpp`；询问投影在 `answer_planning.cpp`；生产可见性概率在 `visibility_forecast.cpp`；分布及区间更新在 `belief_state.cpp` / `joint_world.cpp`。
