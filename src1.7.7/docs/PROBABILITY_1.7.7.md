# 1.7.7 概率模型的生产改进与边界

1.7.7 在 1.7.6 上独立迭代。感知候选已使用有限联合场景的可见性概率区间，并扣除探测造成的终态损失。完整联合行动策略树、询问的多正确答案顺序及参数校准仍未完成。复制的其它文档记录历史版本，以本文件与当前实测报告为入口。

## 生产接入

`RDFW::VisibilityProbability` 在 `visibility_forecast.cpp` 中构造最多 32 个场景，交给 `JointBelief::probabilityBounds`，由 `ProbeProbability` 使用下界。每个场景同时保留显式 at、全部已确认 inside 正边、已确认手持/托盘与柜门。当前单物位置分布只作为参考场景先验，不能再解释为所有物理关系互斥。

可见性是多个原因的并集：物品有当前位置的显式 at，或位于机器人槽位，或任一父容器在当前位置且打开。拥有另一处的闭柜关系不排除显式 at；打开一个父容器也不排除其它父容器。因此真实 Sense 的出现不能撤销另一个正 inside/at 假设，缺失仍可排除“该地点的显式 at”或“同地打开父容器”这个确定可见的见证。

生产只读取公开输入、当前确认事实及仍有效的感知结果。没有读取 SDK 隐藏终态、作者参考动作或答案真值。

## 未覆盖质量与条件更新

设有限场景权重为 `w_i`，未覆盖质量为 `r`，两者合计为 1。对于可见事件 `V`：

```
P_lower(V) = sum(w_i where scene i is visible)
P_upper(V) = P_lower(V) + r
```

范围裁剪至 [0,1]。这些是相对于声明的开发先验及其未覆盖部分的界，不是已经校准的实际成功率。

对公开观察 `e`，各场景似然为 `L_i`，令 `S=sum(w_i*L_i)`。未覆盖部分的观察似然未知，允许在 [0,1] 中变化，采用保守包络：

```
w_i' = w_i * L_i / (S+r)
r'   = r / (S+r)
```

这是已覆盖场景权重的保守下界和未覆盖后验质量的上界，不能称为唯一精确后验。生产把仍有效的逐物品 Sense 出现/缺失作为 0/1 似然；重新构造当前场景时每条有效观察使用一次。独立内核支持事件 ID 去重和一般 [0,1] 似然；当前生产不会持久维护完整世界的逐动作联合后验。

当 `S=0,r>0`，结果保留 `r'=1`，输出 [0,1]，明确显示支持缺失；当 `S=r=0`，更新失败并保留原分布。禁止把未知质量重新分给已枚举世界来制造确定答案。

当前先验仍属开发假设：沿用单物先验权重；未知 inside 共存以及未知槽位分别保留 25% 未覆盖质量，涉及未知父容器地点/柜门时分别只计一半已覆盖质量。超过 32 个场景的尾部、不合法公开支持及旧分布残余全部进入 residual，不重新归一为已覆盖状态。这些常量在查看本轮规划器新题结果前冻结，未根据分数拟合；后续必须用独立数据校准。

## 动作模型与终态

LOCATION 证据新增独立 `explicit_at`。UNKNOWN 表示尚未确认，-2 表示确认无显式 at，非负整数表示地点，地点 0 与无 at 分开。Stage 1 只从实际 at 输入初始化；Stage 2 不确认初始描述或询问。成功拿取、托盘转移、放下、取出、携带移动等按 SDK 动作更新；PutIn 证明显式 at 被移除。该字段进入事务回滚、投影恢复和缓存签名。

模拟 Sense 使用显式 at、槽位和所有父边的并集。模拟 PickUp 不把“开柜内可见”当成已存在的显式 at。终态及零动作捷径优先使用已确认的独立 at；已确认无 at 时，Sense 路线位置不能冒充送达。未知显式 at 时旧路线位置仍用于部分估价，完全分离与全部 SDK 谓词闭合仍需继续做。

询问有多个已确认正确答案时，旧单答案模型无法证明 SDK 选哪条：两个父边，或父边加显式 at/槽位。该候选标记 `unmodeled_truthful_reply_order`，不编造答案顺序概率；正常物理观察与任务继续按公开资格选择。

## 探索收益

原代码对已完成 goto 的丢失仅预留 Move4 和 120ms，等同于假设之后一定返回。1.7.7 先扣每个已确认丢失目标的 40 分；没有完整返回策略时不把损失替换成一个理想动作。继续成本、耗时、约束损失和探索动作本身照常记账。

概率下界描述“获得至少一个相关可见性观察”的机会，仍不是所有后续任务完成概率。多个物体不假设独立：下界取各物体下界的最大值，上界使用求和上界。当前 `expected_gain` 仍含目标机会值与有限继续成本估计，不能称为完整终态收益的数学下界。下一步应让同一反馈策略树覆盖任务、观察、失败与恢复，并比较相对停止的完整收益。

## 开源依据与下一步

本轮再次核对 [pomdp-py Agent/Environment](https://github.com/h2r/pomdp-py/blob/bd0e4392247aebfe9a95b449275237dcc25e7737/pomdp_py/framework/basics.pyx) 的模型/真实状态边界，以及 [POMDPTools 离散更新](https://github.com/JuliaPOMDP/POMDPs.jl/blob/d970a36d6e41b7d6baa8377ce0426c7282bc5025/lib/POMDPTools/src/BeliefUpdaters/discrete.jl) 的似然加权、归一化与零观察质量处理。区间及 residual 处理是本项目自有实现，没有复制外部代码或增加运行时。

下一步：持久的联合动作后验与公开先验；未知柜门的反馈路线；多正确询问的 SDK 顺序模型；完整终态/约束/时间/封顶奖励；执行授权与失败恢复；用新数据校准先验、回答噪声和耗时。每一步都要保留基础分、正式分、真实 G/C/K、时间、硬截止与所有退化。

## 后续怎样校准而不按题目调分

1. 先固定预测事件：当前概率范围指“某次物理 Sense 至少出现一个相关目标 ID”，不能用后续任务是否完成代替它。Ask 的答案正确性、执行成功率和任务完成率要分别记录。
2. 在动作前记录公开上下文、预测区间、支持覆盖、候选及选择原因；反馈后按同一事件记录实际 ID、成功/失败、耗时与最终收益。机器人推理只使用公开信息；评测端的隐藏标签可以用于离线核对，不能反馈进当次机器人或参考路线。
3. 用独立开发数据估计参数，再冻结到下一版本。按门未知、槽位未知、多父、初始误导等分组检查频率、概率区间宽度、支持缺失与耗时尾部。单次观察是 0/1，不能用“0/1 落在预测区间内”当成概率校准通过。
4. 目前只执行被选中的候选，反馈样本存在选择偏差。不能从这些样本推断所有被拒绝候选的成功率，也不能按新题最终分倒推先验。在独立模拟数据中预先设计探测，或为未执行候选保留“没有结果”的标记。
5. 下一批独立留出结构先生成并验证可解性，随后一次冻结对照。任何实际目标下降、假完成、失败动作、截止或成本增加都保留；完整赛题与开发留出分别报告。
