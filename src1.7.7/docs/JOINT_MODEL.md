# 联合隐藏世界与反馈策略树（2026-10-04，开发中）

## 为什么继续改

src1.7.3 能按询问回答选择目标位置验证路线，但目标之外的位置、柜门、手持/托盘未知状态尚未形成联合场景；模拟中的其它弱提示也可能影响路径。在真实题中，先确认目的地再返回取物增加 3 成本，部分题少完成目标。日志中的任务恢复不一定是官方新增目标。需要能比较完整动作序列和最终状态的模型。

本轮联合策略树尚未接入生产 Probe 或取代真实事实层；已经修正生产询问噪声模型的重复地点权重、固定初始回答域及新标签的稳定细分，并收紧离开手持/托盘的证据判断。

## 隐藏状态与机器人信息分开

`JointWorld` 只包含值：机器人位置、物体显式 at/inside 关系、柜门和手持/托盘编号。没有 RDFW 指针、canonical 状态或 SDK 连接。`JointDynamics` 生成物理变化与公开反馈；`JointBelief` 保留多个带权世界，机器人更新的是概率分布。

`JointPolicy` 的分支只能按可见物体集合、动作成功/失败、或带噪询问回答索引；没有隐藏世界编号，也没有逐世界的最优动作入口。规划用同一动作目录对所有假设计算价值，接收到不同公开反馈后才可以选择不同的下一步。

| 反馈 | 模型提供的信息 | 保留的不确定性 |
|---|---|---|
| Sense | 当前可见 ID 集合 | 不直接给柜内外、柜门或手持关系 |
| Open 成功/失败 | 成败 | 失败可能是手非空、柜已开或不在当前地点 |
| TakeOut 成功 | 相应世界转入手持且移除 inside | 未成功世界仍保留其它原因 |
| AskLoc | 按观测似然产生回答分支 | 具体位置回答仍可能错误 |

完整世界之间的位置、门和物品关系可以相关；观察一个物体可以改变同一世界中的其它变量概率，不要求独立边际。当前测试直接提供联合先验。真实输入到联合先验的构造、未覆盖世界和后续再生仍待接入，不能用“支持中没有某个世界”当作物理不存在的证明。

## 按官方动作规则检查

读取官方 SDK `res/evaluate.lp` 与 `src/evaluate.cpp`：手持/托盘物体从机器人位置推导 at，因此 Sense 也可看到它们；只有 inside 且没有显式 at 的物体，才受到关闭柜门的遮挡。官方接受同时具有 at 与 inside 的输入，本内核保留两者，不能强制归成互斥标签。

Open/Close 要求当前位置、空手和相反门状态；PickUp 要求空手、非托盘物体及显式/槽位派生同地，不能因开放柜里看见物品就认定可直接 PickUp。TakeOut、PutIn 和托盘转移分别按 SDK 前提模拟。失败不改变物理状态，但照样收费。Move 到当前地点失败并扣 4。

两条真实关系给出多个正确回答原子时，SDK 取第一个匹配，但排序契约未确定。本轮把这种 Ask 标为未覆盖；物理路径仍可模拟。可移动容器、同物体同时占两槽等暂不支持，明确拒绝，不静默改写世界。

## 联合更新与有界规划

对每个假设执行同一个动作，将相同公开观察的世界合并：

`P(o | b,a) = Σ_s b(s) P(o | s,a)`。

`b'(s') ∝ Σ_s b(s) P(s',o | s,a)`。

Sense 和物理成败由确定性的 SDK 规则生成；Ask 使用独立带噪观测模型。官方随机分支从初始 at/type 条目抽取，条目保留重复；不是在去重后的标签之间均匀抽取。本轮权重模型保留地点出现次数，移动不重建初始回答域。已知世界可冻结自己的初始噪声条目，因此噪声分布也可与其它隐藏位置相关。生产可见初始描述只是代理，仍保留 0.1 未覆盖质量，不能当作已知真实域。新回答标签从未覆盖桶顺序细分，不重置已有权重；细分比例仍未校准。事件 ID 去重，不可能观察不更改分布；未知回答仍是概率模型内的观察，不能自行生成已确认位置。

策略价值使用终态函数，停止值为 `E_b[terminal_score]`。动作值为 `-cost(a) + Σ_o P(o|b,a)V(b_o)`；选择动作和停止的最大值。调用者提供同一个终态评分函数，已经完成的目标不会因为重新观察就再加 40。本轮测试的终态函数覆盖 GOTO、放到目标位置及已完成状态；真实全部任务绑定、约束破坏历史和记分账本尚待桥接。

搜索同时受动作深度（最多 32）、节点数、计算时间和剩余执行时间限制。默认耗时继承 Move 120 ms、其它动作 100 ms，并可传入校准值。搜索耗尽时保留每个观察下明确的停止策略，已找到的值只是一条可行模型策略的下界，`search_complete=false`，不声称全局最优。返回策略不是执行权限。

有残余世界质量时，当前接口明确标为 `residual_support`，不把剩下的世界重新归一为完整真实世界；后续必须实现带覆盖边界的场景抽样/再生和价值上下界。这项缺口会阻止直接接入，不是已经证明无需探索。

## 数学反例与 SDK 证据

两个等概率世界：目标在 1 或 2，机器人起点 0，GOTO 收益 40，Move 成本 4。没有观察时必须选同一个地点，价值为 16；如果逐隐藏世界分别选地点，会错误地报出 36。测试检查模型只能得到 16。

允许询问后，正确分支 0.6、两地点随机 0.3、未知 0.1。收到位置 1 的后验正确率为 5/6，不是 1；询问后按回答选择 Move 的期望终态价值扣成本为 26。未知分支也选择同一后验最优动作。已经确定完成的目标会直接停止，保留 40 而不虚增观察收益。

两个相关世界同时交换源物体和目的地位置，测试检查观察/拿取成败之后可以改变动作顺序，价值不超过知道所有真值的上界。另验证柜门/手状态造成同一 Open 失败的联合后验、异常概率、超时/零节点回退。

修正槽位证据之前，普通测试 268/268，包括继承检查、23 个联合用例、3 个新噪声集成用例及 10 组官方 SDK 对照。SDK 对照逐步比较动作成败、Sense 集合和完整物理关系，再比较最终基础分；每一步的 vstate.lp 保存。另外四组直接让同一联合先验生成策略，随后从 SDK 真实回答选择 Move：正确回答两组各得 34，刻意错误与未知回答两组各得 -6。即使正确回答，后验也未变成 1。首次错误回答 fixture 误以为随机域已去重，失败引出真实 SDK 的重复条目权重，已修正源模型。构建 API 类型错误、SDK 不支持的 id 条件、未注册新标签的失败记录均保留，未修改 SDK。

## 继续完成同一目标

1. 从真实 canonical/弱提示/可信观察构造有覆盖界限的联合先验，保留物理相关性与未覆盖质量；未解释的新回答需要重新生成支持。
2. 让模拟机器人仅收到 SDK 契约下的公开反馈；既有规划器可读取模拟机器人获得的证据，但不能读取隐藏世界。
3. 接入真实任务绑定、官方终态、约束历史与累计成本；比较先取物再验证、先验证再取物以及失败后处置。只有完整授权动作路径可以真实执行。
   特别要区分“确定已完成”与“执行后预计获益”。未知托盘下 TakeOut→PutDown 不足以直接确认两个槽位都排除，但这条路径仍可能有高期望收益。不能因为确定性评分不给分就丢掉机会；也不能为恢复排序而把不充分证据写成事实。
4. 用后来验证且未被中间动作改变的标签校准回答/可见性/耗时，并在留出题、多个种子及全题库上报告 G/C/K、分数、时间、超时与全部退化。

这些接入项尚未完成，本轮的内核检查不等于目标完成。

## 继承测试的不稳定假设

首次内存检查中，继承的询问集成用例假设首次候选有资格就一定会实际执行；重新授权时，部分路线缓存扩大后可使询问净值变负，拒绝执行是正确行为。该用例改用明确的信息先验以测试实际回答反馈；未改生产门槛。另一次继承 guarded 限时路线测试断言失败，单独及整组复跑通过，日志保留。此前内核版本内存检查 251/251；加入最新噪声修改后的完整内存检查 257/257 通过（21.02 秒）。该中间版本普通测试 268/268（3.36 秒）。

## 联合模型暴露的真实证据层缺口

独立诊断 `test-results/development-20261004/slot-authority-diagnostic.cpp` 已复现：同一可见集合既能来自地面物品，也能来自手持物品；真实 hand/plate 尚 UNKNOWN 时，继承的 `IsNotStoredFact` 仍把 Sense + INSIDE=NONE 判成“不在槽位”。诊断输出 hand=-1、plate=-1、not-stored=1，按期望返回失败。概率模型正确保留这些联合世界，但修复前的 canonical 门槛没有利用这一点。

本轮随后修正了生产语义：`IsNotStoredFact` 和 `TerminalChecker` 复用同一判断，不再由 Sense、INSIDE 或笼统 ACTION_SUCCESS 推出离开槽位。每个物体保留手持/托盘排除位：成功 PickUp 的 SDK 前提排除同物体已在托盘上；FromPlate 排除托盘，ToPlate 排除手持，PutDown/PutIn 排除手持并保留先前针对托盘的动作证据。每个槽位分别由可信当前槽位值或这份动作证据排除。单独 PutDown 不证明未知托盘为空；TakeOut 也不额外假定物体不在托盘上。

证据位放在已有 provenance 中，投影与事务自动复制/恢复；重新存放到槽位、inside 重写、事实撤销和外部动作后异常撤回时清除。没有新增事实的 Sense 保留已验证放置证据。加入 12 个单元反例、7 个直接 SDK 对照，并扩大内存失败回滚检查。SDK 中地面、手持、托盘三种真相返回同一 ID 集合时，机器人使用完全相同的弱输入，均保留 UNKNOWN；真实 SDK 操作的成败反馈足够时才确认放置。

最终普通测试 287/287（4.15 秒）、ASan/UBSan/泄漏检查 269/269（24.47 秒）通过。先前 268/257 项是修复前噪声版本的证据，仍完整保留。这项修复不表示联合规划已接入；有限 belief 中的概率 1 仍不能自动写成真实事实。柜内外关系的全部官方独立事实语义、真实先验覆盖、评分桥接与校准仍需继续验证。
