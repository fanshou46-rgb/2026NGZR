# 1.6 后续改进方案：保留感知保障的限时任务组合搜索

日期：2026-09-25  
状态：实施设计；文中的新增接口、参数和测试为待实现内容。  
代码基线：`src1.6`，提交 `6a0fdc6`。  
适用范围：Stage 1、Stage 2，IT／NT 两种输入，沿用当前 5000 ms 评测时限。

## 1. 推荐方案与优先级

在 1.6 的感知、证据判断和全过程约束记录之上，增加限时任务组合搜索。搜索同时比较守约方案、破约方案、现有策略的后续方案及停止方案，再决定下一步执行什么。

实施优先级是：保住现有决策能力 → 统一评分与执行门槛 → 公平比较任务组合 → 改善任务顺序和动作成本 → 扩展对复杂未知信息的处理。

**第一轮保留 1.6 的感知触发规则、纠错和恢复能力。** 感知能否省略暂不作为提分目标。任务排序变化后，感知发生的位置和时机仍须满足证据要求；保留一个函数调用本身不等于保留了感知保障。

本方案中的“最优”指当前约束下推荐的工程方案。限时搜索返回已探索方案中的最佳可行结果；全局最优只在有独立穷举基准的小题上作验证。

## 2. 已有证据与本次优化要解决的问题

### 2.1 已完成的对比测试

用户提供的 `stage1.zip`、`stage2.zip` 各含 30 题。使用同一 SDK、5000 ms 时限和随机种子 `20260924`，每题以 IT／NT 运行两版，共 240 次运行、120 组有效配对。

| 题组 | 1.5 基础分合计 | 1.6 基础分合计 | 观察结果 |
| --- | ---: | ---: | --- |
| Stage 1，每种输入模式各 30 题 | 8630 | 8630 | 目标、计分约束、动作序列均一致 |
| Stage 2，每种输入模式各 30 题 | 8612 | 8599 | 17 题持平，13 题各下降 1 分 |

Stage 2 下降的 13 题中，1.6 的动作序列恰好在 1.5 前增加一次 `Sense`，目标和计分约束数相同。这说明额外感知在这些具体运行中没有改变行动；它没有证明在隐藏事实改变后仍可省略。

与此同时，1.6 的已有验收报告记录了相对 1.5 的收益：高分约束收益题 60 组配对合计增加 672 基础分，变形压力题 80 组配对合计增加 1308 基础分。这些题型的能力是后续改进的保护对象。

## 3. 必须保持的行为

### 3.1 感知与证据

- 保留原有必要感知、位置纠错、失败恢复和终态证据检查。
- 初始描述和弱证据继续按各自可信程度使用；搜索不会把它们升级成实测事实。
- `DryRunSenseIds()` 产生的是依据模型推演的结果。模拟的感知或动作成功只能成为方案假设，不能作为真实世界已验证的证据。
- `SenseCurrentLocationOnly()` 主要获取当前位置的物体信息。看到容器不等于知道容器开闭状态；没有看到物体也要考虑容器遮蔽等语义。
- 远处开闭目标无法通过当前感知直接核实，不代表当前感知对其他目标、位置纠错或路线选择没有价值。
- 对影响破约决定的未知事实无法可靠判断时，沿用 1.6 的感知及保守决策路径。

### 3.2 得分与约束

沿用 `ScoreEvaluator`、`TerminalChecker` 和 `constraint_eligible` 的统一计分。当前内部基础分公式为：

```text
基础分 = 40 × 已完成目标数
       +（已完成目标数 > 0 时，20 × 可计分约束数；否则为 0）
       − 已发生动作成本

移动：4 分；物理操作／人机交互：2 分；感知：1 分。
```

实施时继续用官方 SDK 校验这一口径。官方总分另含时间奖励，不能只用基础分代表总收益。

- 全过程约束一旦失去计分资格，之后恢复表面状态也不能恢复这条约束分。
- 同一约束的损失只计一次；已经发生的损失作为当前状态的一部分处理。
- 目标按最终状态和官方语义计分。`goto` 等目标的满足状态可能被后续移动改变，不能把历史上完成过的目标永久累加。
- 正式重复目标保留计分次数。共享事实的推理可以合并，正式奖励不能随之去重。
- 为搬运、汇聚等生成的临时任务只提供动作，不增加正式目标奖励。
- 搜索启发式只影响探索顺序；批准真实执行时使用完整方案的计分结果。

## 4. 代码组织与接口

复用现有任务求解器和试算路径，新增一个负责组合搜索与选择的模块。以下名称为建议接口，按项目的 C++11 编译要求实现。

| 文件／函数 | 具体工作 |
| --- | --- |
| `candidate_plan.hpp/.cpp` | 扩展任务组、未验证假设、后续兑现条件、批准的约束损失集合和稳定任务标识 |
| 新增 `task_group_search.hpp/.cpp` | 候选扩展、束搜索、状态去重、预算管理、最终方案选择 |
| `BuildTaskGroupPlan()` | 继续生成完整模拟动作；增加可中断检查及异常／取消时的自动现场恢复 |
| `EvaluateShadowCandidates()` | 为搜索提供候选及关系信息，避免每个执行入口重复构造同一状态的候选 |
| `ShouldStartConstraintTrade()` | 逐步改为调用统一决策接口，不再独立维护一套组合判断 |
| 主循环、检查阶段、`MustChooseOne()`、终局回收 | 统一消费决策结果，保存并检查剩余任务组 |
| 多 `goto` 汇聚与临时 `puton` | 作为已有高层方案参与比较，并沿用正式目标计分修正 |
| `score_evaluator.*`、`terminal_checker.*` | 保持统一计分；第二阶段扩展事实依赖与未知分数边界 |
| 构建配置与 `tests/` | 接入新模块、搜索测试、回退测试及官方配对评测 |

建议的决策结果要携带计划，而不是只返回一个允许执行的布尔值：

```cpp
enum class DecisionKind { ExecuteGroup, UseLegacy, Stop };

struct PlannerDecision {
    DecisionKind kind;
    CandidatePlan selected_plan;       // 按顺序执行的任务及模拟结果
    CandidatePlan reference_plan;      // 可比的守约／原策略方案
    std::size_t evaluated_revision;    // 产生结论时的世界状态版本
    std::vector<std::size_t> allowed_constraint_losses;
    bool evidence_sufficient;
    std::string reason;
};
```

任务重排后，正式目标的计分身份仍保持稳定。状态缓存、日志和约束关联使用稳定 ID；需要调用现有按索引工作的代码时，再映射为当前索引。

## 5. 搜索具体怎样进行

### 5.1 搜索节点与任务候选

一个节点表示从当前真实状态出发的一段任务顺序，如 `[A, C, B]`。节点保存模拟终态、动作成本、剩余时间估计、全过程约束记录及未验证假设。

通过 `BuildTaskGroupPlan([A, C, B])` 得到这段任务实际会生成的移动、取放、开关等动作。试算全部发生在隔离状态中，恢复后才考虑真实执行。

候选来源包括当前可用任务、已有多目标汇聚方案，以及以下关系关联的任务：

- 共用物品、容器、起点或目的地。
- 共用同一条可能损失的约束。
- 前一任务使后一任务变得可执行。
- 前一任务暂时损失目标，后一任务可以恢复该目标。

每个节点按模拟后的状态重新判断任务是否可执行、是否已满足。不能仅凭任务在根节点尚不可执行就永久排除它。

允许有意义的恢复任务再次出现。例如目标先满足、后来被另一任务改变，需要恢复。用状态进展和重复次数上限阻止循环，不用“任务 ID 出现过就永远禁止”的规则。

### 5.2 限时束搜索

从空序列开始，扩展单任务，再扩展任务组合。每层只保留少量值得继续尝试的节点，形成下一层搜索入口。

用于第一轮实验的参数：

| 参数 | 初始值 | 用途 |
| --- | ---: | --- |
| 每层保留节点数 | 6 | 限制同时探索的方向 |
| 每节点优先扩展任务数 | 8 | 控制分支数，并覆盖不同关联类型 |
| 主要任务搜索深度 | 4 | 覆盖常见多目标共同承担约束损失的情况 |
| 附加目标恢复任务数 | 最多 2 | 检查能否恢复暂时损失的目标 |
| 单次新增搜索耗时上限 | 25 ms | 包含候选构造、状态复制、模拟及评分 |
| 每题新增搜索累计上限 | 100 ms | 防止多次重规划累计拖慢整题 |

这些是待测参数。实际可用预算还要扣除执行所选方案的预留时间和安全余量；接近截止时间时使用已验证的现有后续方案。

### 5.3 守约与破约方案公平比较

同一搜索器同时保留守约、破约分支，使用相同深度、评价口径和预算分配原则。每轮交替扩展不同类别，避免一种分支先耗光时间。

例如：破约组合净收益 90、单个守约任务收益 60，并不能证明应该破约；两个守约任务组合可能获得 120。最终必须比较能兑现收益的组合。

相同搜索深度仍可能漏掉更远的收益。对少量进入最终比较的方案，使用同一种、受时限约束的后续执行策略继续试算到可比较的停止点；同时保存原 1.6 策略的后续方案作为基准。这一后续模拟也计入搜索预算。

原策略后续模拟需覆盖它实际使用的检查、恢复和多 `goto` 汇聚逻辑。仅把几个 `SolveTask()` 拼起来，不能标记为“完整模拟了 1.6”。这一能力未完成或比较尚未完成时，第一轮采用原策略决定。

### 5.4 如何保留有潜力的方案

每个节点区分两个数：

- **已实现得分**：假如执行完这段方案就停止，可以获得的分数。
- **后续潜力估计**：继续执行关联任务后可能达到的分数，用于安排搜索顺序。

暂时亏分的前缀也可以继续扩展。例如 A 先承担约束损失，B、C 后续共同带来收益。如果只保留当前分数最高的前缀，会过早丢掉这样的组合。

保留节点时兼顾得分、后续潜力、不同约束损失集合和所在位置。至少给可行的守约方向与有希望的破约方向留出搜索机会。

经验估计只用于排序。只有经证明不会低估可达收益的上界，才可用于“这个分支不可能更好”的剪枝；其余被束宽淘汰的分支应记录为资源限制下未继续探索。

### 5.5 状态去重与缓存

当两种任务顺序到达相同的后续决策状态，保留成本更低、可用时间更充足的方案。判断状态相同时必须包含：机器人位置与携带状态、物品位置与容器关系、开闭状态、目标状态、约束失分历史、证据来源、已感知记录及任务启用状态。

不能只比较“剩余任务列表”：物理状态相同但曾经破坏过约束的两个节点，得分不同；物理位置相同但证据不同的两个节点，下一步决策也可能不同。

跨调用缓存至少关联世界状态版本、任务状态、决策相关证据和有序任务组。真实动作、感知、询问或任务状态改变后，失效相关结果；不能只凭未变化的 `world_revision` 就复用所有结果。

## 6. 从搜索结论到真实执行

### 6.1 统一准入规则

把当前风险筛选拆为两类：

1. 物理不可执行、对象无效、动作前提缺失、剩余时间不足：继续阻止执行。
2. 动作可以执行但会损失计分约束：交给方案评分与证据检查决定。

审计 `BuildTaskGroupPlan()` 的 `eligible`、主循环、检查阶段、`MustChooseOne()`、终局回收、多 `goto` 汇聚和底层动作中的相关筛选。逐处接入统一规则，防止评分批准后被旧阈值拒绝，也防止其他入口绕过批准。

第一轮只在已通过验证的新规划路径中开放计分约束权衡，保留未覆盖路径的原行为。试算可探索的计分损失与真实执行被批准的损失都要明确记录，不能通过全局关闭风险检查来实现。

### 6.2 完整组合收益与第一步执行

选中 `[A, B, C]` 后，保存完整计划和 B、C 能够兑现收益所需的条件，真实执行 A。A 完成后：

- 从实际状态重新试算 `[B, C]`，将它作为必须参与比较的候选。
- 已经发生的动作费和约束损失视为既定事实，不重复扣分。
- 如果新的方案更优且证据充分，可以替换剩余计划。
- 如果出现物品位置不符、动作失败、证据冲突或时间不足，重新规划；原因记为计划失效，不能直接误标为整个正式目标永久失败。

在真实破坏不可恢复的计分约束之前，检查完整收益方案可执行、关键假设成立且有足够剩余时间。单个前缀的正收益不是批准依据；组合只要前缀亏分也不应被单任务门槛否决。

### 6.3 感知发生在任务内部时

某些 `SolveTask()` 内部会执行感知或纠错。若新观察推翻计划关键假设，在下一次可能破约的原子动作之前使计划失效并重选。

执行器需要识别“需重新规划”与普通动作失败。已经发生的真实动作及约束损失不能撤销；所谓回退，是从当前真实状态调用原策略重新决定，而不是恢复试算之前的现实世界。

### 6.4 停止也要通过同一个决策入口

将停止作为一个完整候选按当前真实状态计分。选择停止前仍需满足现有终态证据规则，并确认没有已选任务组的必要后续动作被遗漏。

“搜索时间用完”意味着停止扩展，使用已有有效方案；它不等于“机器人立即停止”。

## 7. Stage 2 的适用范围与后续扩展

第一轮优先启用 Stage 1，以及决策所依赖的关键事实已获可靠证据支持的 Stage 2 场景。其余 Stage 2 场景继续使用 1.6 路径，并记录新搜索器的旁路结果。

对含有未知事实的方案，记录它的关键假设及得分范围。一个有效下界严格高于可比候选的有效上界时，可以证明它在建模场景内占优；范围重叠时不能据此证明新方案更好。第一轮不因为未知目标很多就无限感知，也不依据模拟出来的感知结果批准不可逆损失。

第二阶段建立“事实 → 目标／约束／动作前提”的依赖关系。例如多个目标都依赖同一物品位置，应在同一个位置假设下共同计算，避免构造出同一物品同时位于不同地点的高分假想状态。

逐步用相关未知事实数量和可枚举场景数控制计算量，替代固定的任务数边界。24 个以上任务的现有保护路径，要在关联目标、重复目标和历史题回归通过后才扩展。

感知次数优化作为后续独立工作。只有确认不同可能观测不会影响当前及后续选择、也不会增加以后获取信息的成本时，才考虑延后或省略；无法确认则保留。它不进入本轮提分验收目标。

## 8. 运行时间与试算隔离

新增规划预算必须覆盖候选准备、完整快照、模拟、后续试算和评分。单独给搜索循环计时会低估真实开销。

把现有手工保存／恢复现场封装成自动恢复的快照对象。异常、预算耗尽和提前返回都必须还原物体、携带状态、证据、约束记录、任务状态、失败记录、计分器及模拟标志。诊断 ID 等允许变化的字段需单独声明。

预算检查进入每次节点扩展和模拟动作边界，确保长任务组可以及时取消。同步调用不可被中断的部分，要计入最坏耗时余量；仅在循环外检查时间不足以保证 25 ms 上限。

缓存和轻量状态优化在正确性验证之后进行。先测量耗时组成，再决定是否减少快照复制；不要为速度遗漏影响计分或证据的状态。

## 9. 决策流程伪代码

下面展示控制关系，接口名称为设计示意：

```text
DecideAndExecute():
    执行当前条件下原策略要求的感知与纠错
    更新真实状态、证据、目标和全过程约束记录

    如果新搜索模式未启用或当前场景不在已验证范围:
        从当前真实状态执行原策略下一步
        返回

    建立本次预算、停止候选和原策略可比较的后续候选
    把上次所选组合的剩余部分重新试算并加入候选
    frontier = {空任务序列}
    best = 当前最佳完整、可执行且证据合格的方案

    在深度和全题预算允许时:
        对 frontier 中不同类别的节点交替扩展:
            生成未完成任务、依赖任务和必要恢复任务
            对每个新序列:
                在自动恢复的快照内试算动作及后续状态
                检查动作前提、时间、证据假设和约束损失
                更新已验证的最佳完整方案
                收集仍有搜索价值的节点
        按潜力与状态多样性保留下一层少量节点

    对最终候选与原策略做可比的后续评价
    如果比较未完成、证据不足或没有明确改善:
        从当前真实状态执行原策略下一步
    否则如果最佳方案是停止且终态检查通过:
        停止
    否则:
        保存最佳任务组、关键假设及允许的约束损失
        执行其第一个任务
        任务内部发现关键证据变化时，在不可逆动作前重规划
```

保留原策略作为候选有助于控制退步，但搜索耗时和模型误差仍会影响结果。是否默认启用，以后面的官方配对验收为准。

## 10. 实施顺序与阶段交付

| 阶段 | 实施内容 | 完成条件 |
| --- | --- | --- |
| A：固定基线 | 保存 1.6 二进制、SDK、题目、种子、动作与评分；建立必要感知保护题 | 基线可复跑，所有输入有哈希 |
| B：旁路搜索 | 快照自动恢复、任务组合搜索、公平比较、候选及批准原因日志 | 搜索不会调用真实动作接口；恢复后决策状态一致；预算有效 |
| C：受控执行 | 统一资格与执行门槛、保存后续任务组、计划失效后重规划 | Stage 1 和证据充分的 Stage 2 通过反例与回归 |
| D：默认策略验收 | 全部既有题与新增保护题做官方配对，测收益和耗时 | 满足第 12 节发布条件 |
| E：复杂未知信息 | 共享事实建模、得分范围、扩展任务数边界 | 关联未知事实及 24／25 边界题通过专门验收 |

建议采用 `off / shadow / guarded` 三种模式。`shadow` 只收集候选结果，仍有运行耗时，性能评测应单独记录。各阶段按功能提交，发生退步时可以撤回对应策略改动。

本方案沿用当前项目目录，不需要为每一步增加同级项目副本。后续发布版本名及 PR 更新在实际实现验收后确定。

## 11. 测试设计

### 11.1 既有回归集

- 用户提供的 Stage 1／2 共 60 题，分别运行 IT／NT。
- 1.6 已有的高分约束收益题、变形压力题和历史有效赛题。
- 五项现有本地测试，以及真实接口／官方 SDK 对比。
- 明确保护曾经依赖感知避免错误破约、避免无效搬运、识别已完成目标的案例。

未来主要比较对象是原始 1.6；1.5 作为辅助参照。保留本批 13 题的额外感知成本可以接受，不以强制恢复这 13 分作为成功标准。

### 11.2 新增定向题：建议 72 道具体实例

| 组成 | 数量 | 覆盖内容 |
| --- | ---: | --- |
| 六类搜索题，每类 4 题 | 24 | 共享约束损失的正负收益；守约组合优于破约组合；依赖／恢复顺序；重复目标与 24／25 边界；超时／失败回退；终态 `goto` 与临时目标计分 |
| Stage 2 隐藏事实对照题，12 对 | 24 | 同一可见题面、不同真实世界；在目标已完成、位置错误、物品缺失、容器遮蔽等情况下验证必要感知 |
| 从前述题选 12 题，各生成 2 个等价变体 | 24 | 任务顺序变化及对象 ID 等价重命名，检查编号或输入顺序造成的偏差 |

六类搜索题覆盖 Stage 1 和 Stage 2；依赖未知信息的专门断言用于 Stage 2。主测试题的目标／约束理论满分设计在 800–1000 左右，按 `40 × 目标数 + 20 × 约束数` 计算；动作扣分和官方时间奖励单独记录。

高分题中的目标要有明确用途，避免通过大量无关重复任务凑分改变了原本要考查的决策。精确穷举验证另用更小规模实例，不要求它们也达到该分值范围。

边界题必须包括净收益为负、为零、刚好为正，以及负收益前缀连接正收益后续的情形。相同最终得分时，优先验证成本低、证据充分、约束损失少的选择。

Stage 2 对照题改变的是实际隐藏事实，不能把正确答案写进规划器可见输入；等价变体也不能改变任务含义或物理布局。增加“无关物品”时，先确认它不会改变传感器可见性或其他规则。

### 11.3 独立最优解与误判判定

对小规模确定性题，建立独立动作状态搜索，计算可达状态及最佳基础分，再将代表性最优轨迹交给官方 SDK 重放核对。独立基准不能调用被测规划器的 `SolveTask()` 来生成全部候选，否则两者可能共享同一个遗漏。

Stage 2 必须区分知道隐藏真值的评分器与只能获取规定信息的规划器。完全知情的最优动作只能作为分数上界，不能直接用于判定部分可观测条件下的决策错误。需要精确策略比较时，仅在有限的小场景集合上构建具有相同观察能力的策略基准。

未建立精确最优解的题，使用明确的约束保护、必要感知、合法动作和净收益断言；不把“程序跑完了”当成“决策最优”。

### 11.4 运行方法与日志

固定题目、SDK、词典、时限及输入模式，两版交替运行，保存源码和二进制哈希。全量先用已知基线种子；隐藏信息与时间敏感题再使用预先确定的额外种子。只有失败、耗时边界或时间奖励波动需要解释时才重复测试。

每次决策记录：状态版本、任务组、守约基准、原策略基准、预测最终分、关键假设、约束损失、选择理由、搜索节点数、搜索耗时、预算截断原因以及实际动作结果。

汇总至少包括：逐题基础分与官方分、正式目标数、可计分约束数、错误破约／漏做有利组合的断言结果、必要感知是否保留、规划耗时 P50／P95／最大值、超时率和预测误差。

## 12. 默认启用的验收条件

1. 普通题及负收益保护题中，指定必须保住的目标、约束和必要感知均通过；正收益题允许经正确计价的目标／约束取舍。
2. 已有回归集和新增定向集逐题基础分相对原 1.6 无退步，并且至少有明确针对搜索缺陷的题获得提升。
3. 所有精确基准题达到该基准下的最优基础分，或对尚未覆盖的场景保留原策略，不将其纳入默认启用范围。
4. 模拟不污染真实状态，不发出真实环境动作；预算取消、异常和行动失败后的恢复测试通过。
5. 统一门槛后，预定的正收益多约束组合能够执行，负收益组合不会因入口不同而绕过判断。
6. 无新增执行超时；新增搜索耗时符合预算。对时间奖励敏感的题复测后，官方总分若持续退步，应降低预算或限制启用场景。
7. 旁路结果、受控执行与正式评测均有可复查日志，所有差异能对应到具体动作、证据或耗时变化。

若搜索只增加计算量而没有稳定提高最终得分，维持旁路模式。若少数场景出现退步，先将这些场景回退至原策略，再定位模型、搜索或执行衔接的问题。

实施完成后交付：代码改动、必要测试、新旧逐题对比报告、默认参数、已启用范围及回退方式。验收报告以实际结果填写，不预先承诺全部未知题零误判。
