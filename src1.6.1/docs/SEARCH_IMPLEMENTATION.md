# 1.6.1 前期：旁路搜索实施记录

本次交付实现改进方案 B 阶段的旁路搜索基础。默认模式为 `off`；设置环境变量
`RDFW_TASK_GROUP_MODE=shadow` 后，会在现有候选准备完成时运行任务组束搜索，记录守约、破约和立即停止的预测基础分。真实动作仍由 1.6 策略选择。

搜索参数：束宽 6、每节点分支 8、深度 4、最多 2 次目标恢复重复任务；单次预算 25 ms，每题累计预算 100 ms。预算包含候选准备和投影，逐个任务与模拟动作边界均检查截止时间。按共享约束、丢失目标和动作对象关系优先扩展；每层交替保留守约与破约节点。模拟计划使用完整 `ScoreEvaluator` 结果，搜索估值仅供旁路诊断。

`BuildTaskGroupPlan()` 的隔离现场现在由作用域保护恢复。正常结束、投影异常及预算中断均还原物体、携带状态、任务、证据、约束账本、评分器和模拟标志。新增组合投影测试检查两次移动后真实位置、任务和动作成本保持不变；搜索测试覆盖守约/破约公平比较、顺序、亏分前缀、恢复重复任务、零预算及投影异常。

验证：WSL Ubuntu 18.04、g++ 7.5.0 下，原有五项和新增两项本地测试全部通过。用从项目 SDK 源码在同一系统重建的官方评测环境，对 `liuyifan1.0/05.xml`（Stage 1、IT、5000 ms）分别运行 `off` 和 `shadow`：两次都得到官方 298 分、6 个目标、0 条计分约束，十步真实动作序列相同；旁路记录 6 次搜索。现有 `07-existing-four-goal` 官方测试得到基础分 220，满足原断言。

目前搜索任务池仍由当前候选提供，节点状态上的新任务发现尚未完成；还缺完整原策略后续模拟、相同停止点的公平评分、证据充分性比较、任务组持续兑现和统一真实执行准入。因此搜索结果不授权真实破约，也未默认启用。下一阶段需在这些执行衔接和官方逐题配对验收完成后，才考虑 `guarded` 模式。
