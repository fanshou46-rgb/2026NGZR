# 1.6.7.1：退出保护与综合 200 题验证

日期：2026-10-05。基线：`HistoryVersion/src1.6.7` 原版，300ms 安全余量。

本版实施[强化计划](../../docs/PLAN_1.6.7_HARDENING_20261005.md)的首个代码工作包 H1，并补齐测试发现的构造初始化缺口。完整 200 题对照显示原行为保持一致；本轮收益为退出与初始化保护，未证明解题能力提升。

## 代码变化

官方 SDK 限时等待 Plan 线程，期限到达时可能继续调用 Fini。原版缺少规划与清理的互斥。现在 Plan 持有生命周期锁；Fini 先增加退出代次，再等待规划退出后清理。输入读取之后、StopGate 和 RecordAction 边界检查退出请求，专用异常展开当前规划。普通输入或平台异常继续传播。

退出代次避免新 Plan 重置一个布尔取消标记而丢掉已发出的请求。退出后重用、在途成功调用和在途异常调用均有屏障反例验证。SDK 在 RDFW::Fini 之前发送网络 Fini 的顺序保持 SDK 原实现；RDFW 锁保护内部状态，不能主动解除 SDK 网络阻塞。

`isMultiGotoMode` 原先没有构造默认值，候选预览入口可能在 Plan 重置之前读取它。本版初始化为 false；正常 Plan 原本也设为 false。内存检查先发现原缺口，同一构造反例在原版失败，修复后通过。

原生产文件只有 `rdfw.cpp`、`rdfw.hpp`、`CMakeLists.txt` 三个发生变化，逐项见 [source.diff](source.diff)。其它顶层原文件字节相同，原版哈希见 [BASELINE_SHA256.json](BASELINE_SHA256.json)。本版独立目录保存，原版未修改。

300ms 计划预留、5000ms 平台期限、必要感知、任务排序、MustChooseOne、约束交换和 Multi-GOTO 均沿用原版。H2–H5 的关系、重试、路线及探索改造留待独立候选。

- Release/O2 ASan、UBSan、泄漏检查：133/133 通过。该配置不链接未插桩的官方评分库，故少一项评分检查。

## 正式对照协议

复用 `题目/2026_comprehensive_200` 原清单及题目哈希：180 道正常题，20 道刻意非法题。正常题各 90 道 Stage 1/Stage 2；题库含 140 道 fullsolve、40 道 tradeoff、20 道 invalid。

每题 IT/NT，两版共 800 次 SDK 运行、400 组配对，SDK 种子 20260928，一轮。串行交替 AB/BA，默认模式，关闭阶段重型计时；Stage 2 按 SDK 错误线索/询问配置运行。基线与新版使用相同编译参数和原官方脚本。运行期间没有并行编译或证据压缩。

WSL 中的官方 SDK 为兼容编译环境重建版；其 src/include/res 共 52 个文件与原安装逐字节相同，库与服务器二进制因重建而不同，两套哈希均保留。词表仅在临时运行副本转换为 LF；原文件保持字节一致。

以官方评分器答案计算 G（最终目标）、C（20 分约束信用）、K（所有尝试动作费用），基础分 B=40G+20·I(G>0)·C−K。正式分 F=min(SDK 原始分,1000)，保留负分。时间奖励单列，非法题单列，缺失评分不填零。

源码、题目、SDK、编译器、工具、二进制和种子冻结；结束后再次验证。全部首轮结果保留，任何补充运行须写入独立目录。单固定种子的旧题回归用于判断本轮兼容性，不证明新结构题上的泛化提升。

## 复现入口

正式运行：`tests/run_comprehensive_compare.py --output <新目录> --sdk <兼容官方SDK> --sdk-original <原官方SDK>`。默认种子和轮数与本报告一致。

独立复核：`tests/audit_comprehensive_results.py <结果目录>`，重新读取服务器动作、官方 ASP 答案和成绩，与逐运行结果核对。

证据压缩：`tests/package_comprehensive_evidence.py` 按 SHA256 去重存储，重复 SDK 资源仅保存一次；MANIFEST.json 将每个原逻辑路径映射到 blobs/<sha256>，字节长度及哈希逐项保留。归档全部正式/预试运行、两版生产二进制、源码副本、构建记录及初始/最终检查日志；检查构建的中间对象省略。压缩包完成后逐项 CRC/SHA256 验证。
